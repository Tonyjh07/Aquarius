# 会话树关系图 · 设计语言（relation-map）

> **一句话抽象**：以**当前 Head 消息**为中心、按「跳数与条数」预算化展开的、
> **层级即颜色**的有向图——`uigui` 会话历史次窗（winHistory）的形态规格（D112/S3）。
>
> 它的全部视觉张力来自三件事——**中心锚定**、**斥力主导的松弛布局**、**层级即色**。其余都是工程细节。

## 2. L1 名词表

| 术语 | 源语言定义 | 会话树投影 | 必需性 |
|---|---|---|---|
| **节点** Node | 一个可被索引的实体 | 一条**消息节点**（`conversation.MessageID`） | 必需 |
| **结构根** Root | （源语言并入锚点） | **会话根节点**（`Role=root`，`ID` = 会话 ID，无父、空内容，D19）——几何生长的起点 | 必需 |
| **锚点** Anchor | 图所依附的唯一主体；豁免预算、最大权重 | **当前 Head 消息**——焦点、最大权重、`focus()` 的落点 | 必需 |
| **断言** Assertion | 两个节点间一条**有向**关系陈述 | **父 → 子**一条边；箭头 = 对话推进方向 | 必需 |
| **类别** Kind | 关系的封闭语义集合 | **`Role`**：`root` / `user` / `assistant` / `system`（封闭四值，D95 已删 `tool`） | 必需 |
| **版本链** Chain | （源语言未单列） | **断言的种类**：`RevisedFrom` 命中的边 vs 普通追加边 | 必需 |
| **距离** Depth | 节点到锚点的跳数 | 到 **Head** 的跳数（0 = 锚点）——只用于**预算与权重**，不用于几何 | 必需 |
| **层号** Level | （源语言未单列） | 到**结构根**的跳数（根 = 0）——**几何 y 与颜色的唯一依据** | 必需 |
| **权重** Weight | 节点的语义等级，与连接数无关 | `f(类别, 是否在主干上)` 查表（§2.2） | 必需 |
| **摘要** Preview | 节点携带的短文本载荷 | 消息**渲染文本首行片段**（`Snippet`） | 必需 |
| **引用** Ref | 节点指向的详情页地址 | `/goto <id前缀>`（D94 落 `Tail` 语义：切到该版本对话全程） | 必需 |
| **预算** Budget | 同时呈现的节点数上限 | `maxCount` + `maxDepth` + 「共 N · 呈现 M」（A7） | 必需 |
| **视场** Field | 视口中心与缩放倍率 | 中心 = 锚点屏幕坐标；`zoom ∈ [0.5, 1.5]` | 必需 |

### 2.1 最重要的术语拆分：**结构根 ≠ 锚点**

源语言把「唯一、无父、豁免预算、最大权重」压在**一个**概念（锚点）上。会话树里这两半落在**两个不同节点**上，
硬压成一个会立刻冲突（Head 有父、会话根无内容）：

| 半边 | 落在 | 理由 |
|---|---|---|
| **唯一、无父** | 结构根 `Role=root` | 会话根**天然**满足（D19 唯一实根）；它是几何生长的起点 |
| **豁免预算、最大权重、焦点坐标可取得（A8）** | 锚点 = Head | Head 是「用户在哪儿」的**唯一**答案；对话在 Head 处结束，Head 是常态叶端点 |

因此图读起来是：**顶部 = 会话第一层（最早），向下 = 对话推进方向，底部叶端点 = 当前（Head）**；
开窗时**视场居中 Head**（`focus(anchor)`），而不是居中根。

### 2.2 Weight 必须与 degree 解耦（加严）

> **视觉显著性 ≠ 连接度。**

一个只有一条边的节点，与一个「一层挂 5 个版本」的节点，在语义上**不**同重要。
一旦允许「按孩子数定大小」，图就会退化成「分叉点独大」，与语义无关。

- `degree`（孩子数）**只允许影响布局**（角度扇区宽度分配，见 §5.1），**绝不允许影响视觉大小**；
- `weight` 由 `(类别, 是否在主干上)` 查表得出，**表必须写死并被测试钉住**：

| weight | 条件 | 直径（× 基准 dp） |
|---|---|---|
| `w3` | 锚点（Head，含 depth 0） | 1.30 |
| `w2` | 在 Head 主干路径上（`InPath`） | 1.00 |
| `w1` | 不在主干、但**是分叉位点**（存在兄弟版本） | 0.85 |
| `w0` | 其余 | 0.70 |

- **分叉位点不进直径**：源语言的「节点形态」通道在本项目已被**类别**占用（§3.1），
  故分叉由**描边**表达（沿形状的细虚线外环，§3.3）——「有兄弟」这一事实仍然出现，但**不在大小上**。
  版本计数 `i` 画在**节点图形内部**（D121；`n` 暂不落——见 §3.1a）。

### 2.3 版本链：域内事实与可判定边界（**已知限制**）

会话树的版本事实只有一个结构元数据：`Conversation.RevisedFrom`（新 → 旧，**纯结构元数据**）。
`Fresh` / `Carry` / `Clone` 三种 `KeepMode` **不持久化**——D96 的 Clone 也只在拷贝子树**根**记一条。

因此 v1 的**断言种类只分两类**（`EdgeKind`）：

| `EdgeKind` | 判定 | 图形 |
|---|---|---|
| `EdgeSeq` 顺接 | 目标节点不在 `RevisedFrom` 的值集中 | 实线 |
| `EdgeRevise` 版本链 | `RevisedFrom[目标]` 命中 | 虚线 |

- Fresh / Carry / Clone 三者**在树形上已可分辨**（Clone 立即带整棵拷贝子树、Carry 让旧节点成为叶子），
  但**无字段可指名**。v1 合并为「版本链」一种线型，不猜。
- **后续增强（不在 S3 范围，属破坏性窗口可做）**：在域内为修订节点持久化 `keep_mode`，
  则 `EdgeRevise` 可细分三种线型。届时本节升版，图例同步。

## 3. L2 编码契约：通道分配

每个视觉通道只承载**一种**语义，禁止复用。

### 3.1 通道表

| 通道 | 承载语义 | 规则 |
|---|---|---|
| **节点填充色** | `Level mod 4` → **深度色带** | 同层同色，沿树 3~4 色轮换；`Level` 是封闭可枚举的周期量（§3.2 改判） |
| **节点形状** | `Role`（root/user/assistant/system） | 四值四形；形状是源语言未占用的自由通道 |
| **节点直径** | `weight` | 查表 §2.2，**与 degree 无关** |
| **节点描边** | 分叉位点 | 分叉 = 细虚线外环（不改大小，A4 的描边通道）；主干改走**边描边**（见下） |
| **节点卡底色** | 节点填充色 → **同色系淡彩**（D121） | `层色向窗底色靠拢 relCardTintF`：浅色版变淡、深色版自动变深；标签压在卡内 |
| **边线色** | `source` 的填充色 | **边的所有权**——与目标无关（§3.3） |
| **边线型** | `EdgeKind`（版本链） | 顺接实线 / 版本链虚线（§2.3） |
| **边描边** | `InPath`（主干，A11） | 主干边垫一条**窗底色粗线**再压本色细线——「我在看哪条线」画在**线上**而非节点白圈上（D121：白圈把形状切出白口、在卡片里读作贴纸边框） |
| **箭头方向** | 对话推进方向 | 恒为 **父 → 子**（提供者 → 消费者） |
| **标签可见性** | `weight ≥ 阈值`（且 zoom ≥ 下限） | 稀缺资源的二次分配（A5） |
| **字号** | `zoom` | `clamp(12 × zoom, 10, 16)px`，A9 |
| **弧度** | *（缺省）* | 恒为直线，不编码任何东西 |

### 3.1a 节点卡：标签入内（D121）

节点 = **卡片** `[形状徽标 | 标签]`：

- 徽标仍是 `Role` 四形 × `Level` 色的填充形状，居于卡左；卡内上下左右各留内边距
  （菱形尖/空心圆不被切边、分叉虚线外环不越出卡界）；
- **版本下标画在图形内部**（白字居中）：`i`（第几个版本）写在**形状里**、`n` 暂不落——
  `n` 是兄弟总数、读起来要回查；`i` 直接消歧。写进图形而不是标签：节点图形是被
  缩放/预算裁剪后仍然认得出的那部分，版本号属于「我是哪一个版本」的身份信息；
- **分叉虚线外环沿节点自身形状走**（圆走圆、方走圆角方、菱形走菱）——圆节点套方虚线框
  会读成两套语言；
- 标签画在**卡内**（此前在节点右侧外面飘着）：单行，超出走省略号，宽度封顶
  （摘要可达 40 字程，不封顶则一张卡横跨半个视口）；
- 标签不可见时（A5 预算 + zoom 下限）**退化为裸形状**——标签仍是预算，卡不是；
- 卡底色 = 层色向窗底色靠拢（一个公式，浅色版淡彩、深色版自动加深）；
- **卡片占位参与布局**：`relGeo` 把「卡片半宽/半高」喂给求解器，斥力从卡片边缘起算
  （§5.1 R6）；占位**不随 zoom 变**（否则缩放就会改布局，违反 R3）。

> 屏幕几何一律经 **有效缩放 `z = zoom × PxPerDp`** 换算（`toScreen` 唯一定义）：徽标、
> 卡片内边距、边宽、虚线、箭头都乘 `z`，字号走 `sp`（由 Metric 换算）——两套单位各走
> 各的通道，125% DPI 下标签与卡片才不会比例失衡。

### 3.2 改判：颜色的投影对象是 `Level`，不是 `Role`

源语言 A2 规定「颜色是**关系类别** kind 的投影」。本项目**刻意改判**为
「颜色是**层号** `Level mod 4` 的投影」，`Role` 移交形状通道。

- **理由**：对话树的层级本身是最强的阅读线索（越靠下 = 越新 = 离「现在」越近）。
  深度色带让「这段对话有多长、我在第几层」一眼可读，且天然形成**分区节奏**；
  而 `Role` 只有四值、已由形状完全承载。
- **改判未破坏的底线**：颜色仍**不承载独立语义**——它是一个封闭可枚举量的投影，
  图例可以完整解释（「层 1/5/9 = 色 A、2/6/10 = 色 B …」）。A2 的立意（图例与语义不脱钩）成立。
- **代价**：远距离（低 zoom）下形状退化、颜色主导 → 低 zoom 时标签补 `Role` 前缀
  （`你：` / `AI：` / `系统：`），§5.2 有述。

**调色板**：深度色带 = 4 个**新颜色令牌** `depthMap[0..3]`，深浅两版各一套，
按 §15.4/D61「加色不改代码」纯数据预设落（`palette` 结构增 `depthMap [4]color.NRGBA`）。
浅色版以品牌色 `#00AEEF` 为首色族（与 logo/发送键同源）；深色版压低明度、
保证相邻色相在深底上仍可分辨（相邻两色相 ≥ 40°）。

### 3.3 边：所有权 + 类型 + 关系三元组

```
(source色, source层号)  ──箭头──>  (target色, target形状)
      └─ 谁在往下长 ─┘                └─ 谁接话 ┘
```

- **边色 = source 的填充色**（= source 的层号色）——它让「谁依赖谁」与「谁断言的」解耦：
  一条蓝边意味着「一个第 n 层节点往下长了一条边」，无论目标是什么类型。类型由**目标形状**承载。
- **主干描边**是节点通道（§3.1），不是边通道——边不区分主干/支线，避免与线型冲突。
- **分叉位点**的细虚线外环与主干实心亮环可叠加（同一节点既是主干又是分叉位点很常见）。

### 3.4 关系陈述文案（`statement`，§6.3 派生函数之一）

悬停节点时的一行陈述，**必须自足**（不要求用户回查 tooltip）：

| 情形 | 文案 |
|---|---|
| 主干上游 | `你：上一轮你说的话（当前对话的主干）` |
| 主干下游 | `AI：对上一轮的回答` |
| 非主干版本 | `你：第 2/3 个版本（修订而来）——未走的分支` |
| 系统节点 | `系统：人格快照（会话首节点）` / `系统：压缩摘要（水位节点）` |
| 会话根 | `会话：<标题>（第 1 层，共 N 条消息）` |

## 4. 公理集

这是可被**检验**的部分。每条公理都给出违反后的后果与**守门测试**。

| # | 公理 | 违反后果 | 守门测试 |
|---|---|---|---|
| **A1a** | 结构根唯一且无父 | 多根 → 布局无处生长；树合法性已由域内不变量保证（D19） | `deriveLevels` 恰有一个 level=0 节点 |
| **A1b** | 锚点在任何预算下恒存在且豁免预算 | 图失去中心，退化为无边界的力导向毛球 | `budgetFilter(maxCount=1)` 结果 == `{Anchor}` |
| **A2** | `kind`/`Level` 是封闭集；颜色是其**投影**而非独立属性 | 图例与语义脱钩，颜色沦为装饰 | `paletteOf` 是 `Level mod 4` 的纯查表（无散落分支） |
| **A3** | 断言方向恒为 父 → 子 | 箭头语义不可读，必须回查 | 每条边的 `from`/`to` 满足 `level(from) < level(to)` |
| **A4** | `weight` 独立于 degree | 分叉点支配版面，语义信息丢失 | 性质测试：把某节点孩子数改成 5，`weightOf` 不变 |
| **A5** | 标签是**预算**，`weight` 低于阈值者不显形 | 缩到极限标签糊成一片 | `labelVisible` 阈值单测 + 缩放时标签数单调不增 |
| **A6** | 节点与断言**联合**过滤；被裁掉节点所涉断言一并消失 | 悬空边 / 边数与节点数不一致 | 切片后 `visibleEdges ⊆ visibleNodes × visibleNodes` |
| **A7** | 总量与已呈现量**同时可见** | 用户无法判断看到的是全貌还是切片 | 状态行文案恒含 `Total` 与 `len(visible)` |
| **A8** | 锚点坐标必须可被**重新取得**（作为布局器输出，不窥探内部结构） | 「回到当前」失效——力导向唯一的空间锚 | `centerOf(anchor)` 契约测试；`focus()` 后锚点在视口中心误差 ≤ 1dp |
| **A9** | 字号 = `f(zoom)` 且钳制；**越界降级为平移** | 缩放时字号失控；越界静默失效 | 字号钳制单测 + 越界手势转 `pan` 的状态机测试 |
| **A10** | 每个非根节点携带 `ref`，点击 → 定位该节点 | 图从「索引」变成「死巷 dead end」 | 点击节点注入的 `inCh` 载荷 == `/goto <id>` |
| **A11** | **主干可辨**：Head 路径必须一眼可辨（`InPath` 边描边 + `weight ≥ w2`） | 图无法回答「我正在看哪条线」 | `InPath` 集合 = 根到锚点的唯一路径（性质测试：集合恰为一条路径且长度 = `depth(anchor)+1`） |
| **A12** | **临时固定是非持久的**：拖动期间节点钉在指针下，**松手即恢复自由** | 图被拖乱后回不去，用户失去对图的掌控 | 拖拽状态机测试：松手后 `dragNode` 清空、松弛至收敛即停；`/goto` 不被误投 |
| **A13** | **开窗即适配**：首帧视场装得下**整棵可见树**（不止锚点） | 开窗只看到图的一角，用户以为树就这么大 | `fitView` 后每个可见节点的屏幕坐标落在视口内（帧测试逐点断言） |

**A7 的反直觉之处**：显示「共 134 个」而只画 51 个是**诚实**的。多数实现会藏起这个差异。
**预算制图的可信度来自于承认自己是切片。**

## 5. L3 行为契约

### 5.1 布局：只规定「性格」，不规定「算法」

布局是**可替换轴**（§8）。本项目的性格 = **斥力主导 + 层序投影 + 兄弟槽位**
（源语言源实现是纯力导向；本项目加层序与槽位使其「更像树、自上而下生长」）。
契约只约束结果必须满足的性质：

| 要求 | 含义 | 本项目落地 |
|---|---|---|
| **R1 初始无位置** | 不接受预设坐标；首帧由模拟产生 | 首次布局从**确定性槽位**（兄弟并排 + 边静息长度）起迭代 |
| **R2 软收敛** | 迭代到动能低于阈值，而非固定迭代数 | `kinetic < eps` 即停；上限 `maxIter`（spike 定） |
| **R3 稳定态静止** | 收敛后停止消耗资源（可被交互重新唤醒） | 收敛后不再迭代；平移/缩放**不**触发重排；数据变更 / rebudget 才重排。**唯一例外**：拖拽节点的交互态（§5.2 `drag(node)`），松手锚消失即恢复 |
| **R4 弱语义约束** | 只要求「子恒在父之下」 | 层序投影（`y = level·rowGap ± jitter`）**硬**满足 = 180° 硬上限；横向不加结构约束 |
| **R5 度数解耦** | 高度数不得把邻居推出视野 | 斥力按 `degree` **限幅**（`min(k, kMax)`）；卡片接触推力封顶 |
| **R6 卡片不深压** | 节点卡要装标签 ⇒ 斥力**从卡片边缘起算** | 两卡相叠时按水平穿透深度线性推开（穿透有界，不越界） |

**每轮迭代 = 斥力 + 边弹簧 + 层序投影**（**只动 x**；y 被层序投影钉死）：

```
1. 斥力：任意两节点互斥，系数 min(kRepel·deg(pi)·deg(pj), kMax) —— R5 限幅
2. 弹簧：子被拉向「父的 x + 静息偏移」（软弹簧 = 长边；弱则斥力胜出、树铺得开）
3. 接触：两卡相叠（水平穿透 > 0 且竖直重叠）→ 按穿透深度线性推开（R6，封顶）
4. 投影（层序）：y = level·rowGap ± 确定性行内抖动（jitter < rowGap/2 ⇒ 父子严格向下）
```

**D121 改判：角度硬投影废除**。原设计每轮把子角度**硬夹**进父扇区——硬约束会把斥力
原样顶回去（卡片越宽压得越死、拖开也推不动），且「扇区不破」这条不变量让性质测试
断言的其实是投影本身而非布局质量。现改为：

- **兄弟并排由构造保证**：同一父的 m 个孩子按分配角排序，等距铺在 `(m-1)·pitch` 的
  **槽位**上（`pitch = max(卡片宽, 静息长度) + 间隙`）——不靠斥力挤出来；
- **扇区降级为初值/顺序**：只提供槽位的相对位置（`t ∈ [0,1]`），不再每轮夹角；
- **方向性约束由层序投影承担**：子恒在父之下，即角度 < 180°（R4）。

**可测性口径（力导向不可测坐标的应对）**：坐标不确定 ⇒ **断言不变量**，不断言坐标。
可断言：层序严格单调（`level(parent) < level(child)`，= 180° 硬上限）· 卡片穿透有界
（R6）· 动能降至静止 · 无 NaN/坐标爆炸（有界盒）· 同输入可复现（两次运行逐点相等）。
**确定性的部分**（层号、槽位、调色板、权重、预算、标签阈值）全是纯函数，逐个测。

### 5.2 交互语法（动词表 → GUI 手势）

| 动词 | 手势 | 契约 |
|---|---|---|
| `fit(view)` | 开窗即用（重排后同款） | **整棵可见树适配视口**（按卡片外接盒取最小 zoom，对准盒心），zoom 仍夹 `[0.5,1.5]` |
| `focus(anchor)` | 状态栏「回到当前」按钮 | 视场居中锚点（A8），**不重置 zoom** |
| `pan(dx,dy)` | 拖拽空白处 | 平移 |
| `drag(node)` | **按住节点拖动**（D121） | 该节点**临时固定**于指针（抓取点保持）→ 每帧带固定点松弛、周围被斥力推开；**松手即恢复自由**并自然收敛（**非持久固定**） |
| `zoom(f)` | **滚轮** | `zoom` 夹 `[0.5,1.5]`，字号同步（A9）；**越界后同一手势改为纵向 pan** |
| `inspect(node)` | 悬停节点 | 出示 `Snippet` + 一句话关系陈述（§3.4） |
| `resolve(node)` | 点击节点 | 投 `/goto <id>`（经输入通道，`Tail` 语义 D94）→ 主窗清屏回放 |
| `rebudget(limit)` | 状态栏「+ / −」与「展开全部」 | 重新过滤并**就地过渡**，**不重置视场**（R3：触发一次重排后仍收敛静止） |
| `filter(kind)` | 图例点击 | 按**深度色带**（`Level mod 4`）显隐；节点与边**联合**过滤（A6） |
| `reset()` | 「回到当前」/ 双击空白 | = `focus(anchor)` |
| 右键菜单 | 悬停节点右键 | 改名 / 删除 / 复制 ID（TPM 管线，D72；平台层 D111 已抽象） |

**缩放契约（A9）的要点**：超出钳制区间后不再缩放，而是**把模式从「缩放」切换为「纯纵向平移」**。
这是把「继续放大没有意义」转化为**可用行为**，而非静默失效。字号区间 `[10,16]px` 是**排版可读性**硬约束。
低 zoom（≤ 下限）时标签改显 `Role` 前缀（§3.2 代价条目）。

### 5.3 生命周期状态机

```
        ┌──────────┐
        │ RESOLVING│  数据未达 / 预算未定；不呈现任何布局
        └────┬─────┘
             ▼
        ┌──────────┐  首帧即「涌现」——动效是布局收敛的副产品，不是独立入场特效
        │ SETTLING │  （迭代中；只绘已收敛部分，避免抖动感）
        └────┬─────┘
             ▼
        ┌──────────┐◄──────────┐
        │ SETTLED  │───────────┤ inspect / resolve / pan / zoom / filter
        └────┬─────┘           │
             │ rebudget        │
             ▼                 │
        ┌──────────┐           │
        │ SETTLING │───────────┘
        └──────────┘
```

**设计要点**：「入场动画」与「布局收敛」是**同一个过程**。把它硬拆成「动画时长 + 回调 + 延时 + 淡入」
四段属于 L4 偶然实现，**不应进入设计语言**。本项目取「就绘收敛中的位置」这一最省实现的口径：
无需额外时间线与回调，抖动自然被收敛吸收。

### 5.4 窗形与性能纪律

- **窗形**（DESIGN §15.7 常规窗，无 ULW/无置顶/无位置记忆）：**左栏会话选择（列表）+ 右栏关系图 + 底部状态栏**。
  尺寸由 520×560 调整为 **720×560**（min 620×360），左栏固定 200dp，右栏自适应。
- **状态栏**恒显（§6.4）：`共 N 条 · 呈现 M` + zoom 百分比 + 「−/＋」预算 + 「回到当前」+ 色带图例。
- **性能纪律**：
  1. **视口裁剪**：只绘制与视口（含 20% 外扩）相交的节点与边；
  2. **懒重排**：平移/缩放/悬停**不**触发重排（与主窗「心跳唤帧」纪律同款，D84）；
     **例外**：拖拽交互态每帧走 `relFrameIter` 步（帧预算 `relSettleFrames` 封顶，
     收敛即停——交互态也守「稳定态不烧资源」）；
  3. **预算上限**：节点数超 `hardCap` 时优先收窄 `maxDepth`（砍远端整层）而非逐个截断，
     保证「主干完整 + 远端按层消失」的语义（A6）；
  4. **档位（spike 实测后定，D121 复测）**：Ryzen 7 8700F 上一次性全解
     50 ≈ 0.09ms、200 ≈ 6.6ms、500 ≈ 72ms（O(n²)·迭代；角度硬投影废除后迭代数上升，
     一次性重排变贵但仍是「数据变更才发生」的一次性开销）；`hardCap = 240`。
     拖拽单帧 = `relFrameIter/relMaxIter` 倍的一次全解（200 节点 ≈ 0.5ms，可接受）。

## 6. 数据契约

### 6.1 `port` 侧只读快照（新增于 `internal/port/tree.go`）

```
TreeGraph {                    // D112②：整树只读快照，一次原子发布（复用 D80 发布点）
  Anchor : MessageID           // 当前 Head —— 锚点（A1b）
  Nodes  : []GraphNode         // 按 (Level, CreatedAt, ID) 定序 → 布局可复现
  Total  : int                 // 节点总数（A7 的「共 N」）
}

GraphNode {
  ID          : MessageID
  Parent      : MessageID      // 结构根为空串
  Role        : Role           // root/user/assistant/system（类别，§3.1）
  Snippet     : Text           // 渲染文本首行片段（摘要）
  CreatedAt   : Time
  EdgeKind    : EdgeKind       // 与父边的关系：EdgeSeq | EdgeRevise（§2.3）
  SiblingIdx  : Int            // 自身在同父中的下标（版本 i/n 的 i，D80 同口径）
  SiblingCount: Int            // 同父孩子总数（n）
}
```

**分工纪律**：`port` 只给**树事实**。`Level` / `Depth` / `InPath` / 扇区 / 坐标 / 配色**一律不在 port 里**——
它们是 UI 侧派生量。这既守铁律 5（UI 不得直读 store），也守 D80 口径
（快照是**展示口径**，不参与推理装配）。

**发布**：app 侧沿用 D80 同款 `atomic.Pointer[快照]`，发布点仍是「构造完成 + 每次 `Handle` 返回前」
（树变更只发生在 `Handle` 内）。UI 事件循环 goroutine 无锁读，**只读、无变更入口**。
右图数据面无需扩展到「任意会话的树」：左栏点会话 = 投 `/switch <id>`（D75 已有），
app 换会话后同款发布点自然重建快照，右图自动重锚到新会话的 Head。

**左栏数据面**（新增只读端口，D80/D103 同款反向端口：app 实现、UI 消费）：

```
SessionLister { List() []SessionSummary }
SessionSummary { ID, Title, UpdatedAt, Messages, Current }
```

### 6.2 UI 侧派生量（纯函数，`uigui` 内）

| 派生量 | 定义 | 复杂度 |
|---|---|---|
| `Level` | 到结构根的跳数（根 = 0） | O(n) 迭代 |
| `Depth` | 到锚点的跳数（锚点 = 0） | O(n) 无向遍历 |
| `InPath` | 根 → 锚点唯一路径上的节点集合 | O(n)（A11） |
| `Visible` | 预算切片结果（节点集 + 边集） | O(n log n) |
| 扇区 | 每节点的子角度区间（宽度 ∝ clamp(子树规模)） | O(n) |
| 坐标 | 斥力 + 弹簧 + 双投影的收敛结果 | O(n²)·iter（有界） |

### 6.3 渲染层唯一需要实现的派生符号

```
visibleNodes(G, budget)     → [Node]       // 锚点恒留；其余按 weight 降序截断（A1b, A6）
visibleAssertions(G, nodes) → [Assertion]  // 两端都在 nodes 中的断言（A6）
colorOf(n)                  → 深度色带[Level mod 4]
cardTintOf(n)               → 层色 → 同色系淡彩（节点卡底，D121）
shapeOf(n)                  → Role 四形
scaleOf(w)                  → 直径（查表，degree 无关，A4）
strokeOf(n)                 → 分叉虚线环（主干走**边描边**，D121）
cardHalfOf(n)               → 卡片半宽/半高（喂给布局器：斥力从卡片边缘起算，R6）
labelOf(n, zoom)            → 可见? / 文案（weight 阈值 + Role 前缀，A5）
statementOf(n)              → 一句话关系陈述（§3.4）
centerOf(anchor)            → Point        // 布局器输出，不窥探内部（A8）
boundsOf(visible)           → Box         // 视场适配（A13）
```

### 6.4 状态栏口径（A7 的落点）

```
会话：<标题> · 共 N 条 · 呈现 M    [−] [＋]  展开全部    缩放 100%    [回到当前]
图例：▨层≡1(mod4) ▨层≡2 ▨层≡3 ▨层≡4    形状：□你 ●AI ◇系统 ◯会话根
```

`N` 恒来自快照 `Total`，`M` 恒为实际绘制节点数——两者**不得**由同一个数推算（A7 的诚实性）。

### 6.5 抽象成立的判据

所有力导向迭代、收敛、tooltip、缩放、culling 都在 §6.3 的九个符号**之外**——
它们是**可替换的实现**，不是语言的一部分。

> 一个新后端若能在**不理解 Gio 任何概念**的前提下，仅凭 `TreeGraph` 快照 + §6.3 符号
> 渲染出**语义等价**的图，则抽象成立。

## 7. 必要 vs 偶然（剥离清单）

| 属于设计语言 | 属于偶然实现 / 缺陷 |
|---|---|
| 根/锚点拆分（§2.1） | 用 `nodes[0]` 当锚点的字面判断 |
| 颜色 = `Level mod 4` 的投影（§3.2 改判） | 调色板散落在绘制代码里的 `switch level` |
| 权重独立于 degree（A4） | 具体直径数值 1.30/1.00/0.85/0.70 |
| 类别 = 形状（A2 移位） | 形状绘制的具体路径数据 |
| 标签 = 预算（A5） | 阈值具体取值 |
| 节点与边联合过滤（A6） | **未做**——只过滤节点、边留给渲染器兜底 |
| 总量/已呈现并显（A7） | 由 `len(nodes)` 兼充「共 N」（把切片说成全貌） |
| 锚点坐标可取得（A8） | 读布局器私有字段 / 每帧重算锚点位置 |
| 字号钳制 + 越界降级为平移（A9） | `[10,16]` 像素、`1.49999` 魔数补偿 |
| 主干可辨（A11） | 用「最后绘制的边」冒充当前路径 |
| 拖拽 = 临时固定、松手恢复自由（A12） | 把拖拽做成**持久手动布局**（拖到哪钉到哪，松手不回弹） |
| 开窗即适配整树（A13） | 只居中锚点、把「没看到的」留给用户自己平移发现 |
| 标签入卡 + 卡底随层色（D121 §3.1a） | 标签画在节点外侧、卡底用固定灰（浅色版与纯白窗底读不出卡片） |
| 斥力从卡片边缘起算（R6） | 按中心距排斥（卡片必然压字）、或靠角度硬投影顶住斥力（D121 前的病） |
| 断言自带种类（§2.3） | **由 source 的 kind 反推版本链**（D96 事实：应查 `RevisedFrom` 显式映射） |
| 两态生命周期（§5.3） | 动画时长 + 回调 + 延时 + 淡入的四段式 |
| — | **`depth` 永不产出 0**（锚点自身不算距离——本项目显式给 0，`depthMap`/预算/权重都依赖它） |
| — | **`n <= maxCount` 的 off-by-one**（多画一个） |
| — | **边悬空**：裁掉节点后边仍在（违反 A6） |
| — | **零值 `relPin{}` 把结构根悄悄钉死**（Go 零值 Index=0）——故「无固定」用显式 `Valid` 表达 |

### 10.2 与主窗转写区的纪律对齐

- 本窗**不接**主窗专属机制：无 ULW 形状位图、无位置记忆、不置顶、无拖拽把手（§15.7）。
- 滚轮在本窗**不参与**行级手势（D71 滚轮钉点只管主窗转写区）——故「滚轮=缩放」安全。
- 缩放与 `ui.scale`/`ui.font_size`（D90 两旋钮）的关系：本窗 zoom 是**窗内视场倍率**，
  与全局元素缩放正交；字号区间 `[10,16]px` 是 A9 的排版硬约束，**不随**全局旋钮突破。
- 长按/右键命中复用 D72「武装-原位抬手」手势纪律，不与滚轮缩放抢事件。
