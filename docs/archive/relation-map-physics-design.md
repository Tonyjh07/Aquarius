# 关系图「全程物理动画」重构设计（D124 / D126 修订）
<!-- docs-sync: 2026-10-23 @ 80ef6ae -->

> **已存档（2026-10-23）**：本稿记录的是 D124/D126 那一代「边弹簧 + 阻尼 + 树锚」力积分的
> 推导与实测。生产物理后来改采源算法（D128；形态与现状见 docs/relation-map-design.md 的
> §5.4），本文的结论与参数**只代表当时**，此后不再随代码更新。
>
> 状态：**已批准并实现（2026-10-09，D124；同日按 D126 修订）**。对应
> `internal/adapter/uigui/relmap_layout.go`（布局内核）与 `relmap_frame.go`（帧层）的重构
> 已落地。本设计**取代**现有「一次性求解 + 静止 + 入场 lerp」的布局/动画方案，不沿用
> `relation-map-design.md` 的旧口径（用户指示）。
>
> 一句话：**布局器改成常驻物理模拟**——节点间边弹簧 + 阻尼 + 速度积分 + 树锚，
> 树在任何时刻都是「活的」；拖节点 = 钉住一个质点，整棵树经弹簧按物理规律动起来，
> 阻尼使其自然收敛；**松手即把当前位置写回静息槽位**（拖完留在原地，不弹回旧形状）。
>
> 落码差异（与草稿的偏差，详见 decisions.md 的 D124 / D126）：
> ① 边弹簧改**父子等大反向**（牛顿第三定律，原草稿只对子施加——否则共振不收敛）；
> ② ~~每节点静息锚~~ **D126 废除**（用户要求「不锚定节点，使之能自由移动」）——改由
>    **树锚**（整树盒心 → 静息盒心的均匀外力）+ 静止时把整树平移到锚点兜住位置；
>    配合 **松手采纳槽位**（`adoptSlot`：把被拖节点当前位置写回 `restOff`/`restGap`，
>    子树递归重算；槽位按消息 ID 持久，rebuild 恢复）；
> ③ 卡片接触推力取代长程斥力（D126）：按轴隙、沿最小穿透轴推，静息布局即平衡态；
> ④ 子步数 6 → **12**：高度数节点的「呼吸」模态 ω=√(k×(deg+1)) 会越过半隐式欧拉的稳定
>    边界 ω·dt<2，不足会撞出「速度被限幅钳住、阻尼失效」的极限环。当前档位最高频是
>    纵向（ω=√(2×240)≈22，ω·dt≈1.8 < 2）；
> ⑤ 播种由「全叠根点」改为**向盒心收缩 `relSeedShrink`**（D126 修订：向根点收缩会让深链
>    的盒心起点离锚点几千 dp、展开被树锚猛拽 ⇒ 平移过冲 + 极限环；向盒心收缩 ⇒ 播种
>    盒心 = 锚点，展开是纯扩张）。
>
> **D126 的最终参数档位**（用户两轮实测迭代：先要「约 10s 收敛看看效果」→ 实测「太晃」
> →「提高阻尼」）：弹簧按轴 `relPhysSpringX=1.0` / `relPhysSpringY=2.0`、阻尼按轴
> `relPhysDampX=relPhysDampY=0.5`、树锚 0.03、每帧 12 子步；**力限幅**
> `relPhysFMax=12`（挡「VMax 钳位打败阻尼」极限环）；实测真实会话树收敛 40 帧/0.7s、
> 单次轻过冲 ~55dp、平衡偏差 0.0dp。软弹簧（0.012 档）已实测否决：势能面太平卡局部极小、
> 接触力顶离槽位 100+dp。参数固化见 `relmap_layout.go` 顶部 const 块与 D126。
>
> **D126 一并落地的绘制修正**（用户实测报障）：方形节点虚线外环的直边贴 ±r（旧版画在
> 弧心列 r−cr 上，虚线内缩一个角半径画进徽标里）；版本下标/卡内标签改用**精确约束 +
> Center** 排版（旧版 Constraints.Min=(0,0) 时 Gio 的 Center 等于不平移，数字贴在左上角）；

## 1. 目标与动机

### 1.1 用户反馈（2026-10-09）
- 现状「不拖直接不动」：布局一次性解完就静止，树是「死的」。
- 用户要的**不是入场动画**（D123 的 lerp 方案被否），而是**全程都能动**：
  节点间**弹簧、接触推力**，有**阻尼**（D126 落码版；初衷的「斥力」见 §2.2 ③）；
  用户拖节点时，**整棵树都按物理规律动起来**。
- 隐式要求：60fps（200 节点）、收敛后不烧资源（R3）、拖拽不瞬跳、树保持可读。

### 1.2 现状问题（为什么重构）
| 现状 | 问题 |
|---|---|
| `relax()` 梯度下降（`x += F·gain`，无速度） | 无惯性 → 拖拽只推、不荡；树静止后是死的 |
| 一次性全解 + 静止 | 「不拖直接不动」 |
| 入场动画 = 根点 lerp | 是「特效」，不是物理；按下即打断 |
| y 层序硬投影 | 与 2D 物理冲突（被拖节点 y 被钉死） |
| 拖拽 = 每帧 `relax(relFrameIter, pin)` | 增量但无动量传递，整树响应弱 |

### 1.3 目标
1. **常驻物理**：任何时刻树都是一个可被扰动、会按物理回应的系统。
2. **整树响应**：拖一个节点 → 边弹簧带动子树、接触推力推开邻居、动量在树间传播，整树动起来。
3. **阻尼收敛**：扰动消失后 ~1s 内自然静止；静止即停帧（R3 不烧资源）。
4. **可读**：静止态 = 规范树形（层距 + 兄弟槽位），不缠绕。
5. **60fps @ 200 节点**（≤ hardCap 240）。

## 2. 物理模型

### 2.1 质点
每个节点 = 一个质点，质量 `m = 1`（可选：`m = weight`，先取 1 简化）。状态 = 位置
`(x, y)` + 速度 `(vx, vy)`。世界坐标 dp，y 向下（对话推进方向，与现状一致）。

### 2.2 力（每帧累计到 F）

**① 边弹簧（结构性主力）**
子节点 `i`（父 `p`）被拉向「**父当前位置 + 静息偏移**」（D126 修订：纵向层距从硬编码
`relRowGap` 改为每节点的 `restGap[i]`——松手采纳槽位要能改它；横向偏移本就是 `restOff[i]`）：

```
restTarget_i = ( x[p] + restOff[i] ,  y[p] + restGap[i] )
F_i += kSpring · (restTarget_i − pos_i)
```

- `restOff[i]` = 兄弟槽位横向偏移（沿用 relAssign 扇区序 + 卡片宽 pitch，见 §3）。
- `restGap[i]` = 纵向层距，默认 `relRowGap = 72`；用户手动摆放后可变（adoptSlot 写回，
  钳在 `relRowAdoptMin/Max` × `relRowGap` = 54~144 之间）。
- 关键性质：**子树随父移动**——父被拖走，子被弹簧带着走（拖拽沿树传播的机制）。
- 静息时（无外力）`pos_i == restTarget_i` ⇒ 整树 = §3 的静息树形。

**② ~~根锚~~**（D126 修订：**废除**，改**树锚**——根被拉向原点会与「子树随父移动」打架，
且只钉根不钉整树；见下方 ③'）

**③ ~~斥力（2D 长程）~~**（D126 修订：**废除**，改**卡片接触推力**——长程斥力下平衡态比
静息布局宽 30%~56%，视场按静息盒适配装不下整树；见下方 ③'）

**③' 卡片接触推力（D126 落码版）**
全对（**排除祖先-后代对**——父子/链的间距由弹簧定义，互斥会让它们打不拢；判定用 DFS 序
区间 `tin/tout`，O(1)）：

```
对 i<j 且非祖先-后代：
  dx = x_i − x_j ; dy = y_i − y_j
  轴隙 px = relSlotGapDp + halfW_i + halfW_j − |dx|   // 水平：扣掉两卡半宽
       py = relSlotGapDp + halfH_i + halfH_j − |dy|   // 竖直：扣掉两卡半高
  if px ≤ 0 或 py ≤ 0: 跳过           // 至少一轴分得够开 = 不接触
  pen = min(px, py)（限幅 relPhysPushMaxDp）
  f = pen · relPhysPushK
  沿**最小穿透轴**推（px<py 走 x，否则走 y；同轴叠合给确定性微偏保证反向），等大反向
```

- 平衡点 = 「轴隙恰等于槽隙 relSlotGapDp」⇒ **静息布局本身就是平衡态**（视场基准成立）。
- 沿最小穿透轴而不是中心连线方向：斜推会把卡片推歪、增出力臂抖动（D126 实测修）。
- 等大反向 ⇒ 动量守恒；限幅防深压（密集分支点零重叠不可达，只钉「不深压」）。

**③'' 树锚（D126 落码版）**
每子步算整树包围盒心，施加**均匀外力** `relPhysTree × (锚点 − 盒心)` 到每个节点：

```
F_all += relPhysTree · (restBoxCenter − boxCenter(pos))
```

- 均匀 ⇒ 只平移、零内部应力 ⇒ 单个节点完全自由（可拖到任何位置并留在那里）。
- 静止时再把整树平移到锚点（`snapToAnchor`，纯平移不改相对位置 ⇒ 下一帧仍静止；
  pin 期间不平，否则被拖节点会亚像素闪跳）⇒ **静止态盒心精确等于锚点**。
- 锚点 = 静息布局包围盒心 = `treeBox`/`fitView`/`recenterTree` 的同一个点。
- 力限幅 `relPhysFMax`（与弹簧同口径）：巨幅偏离时限幅，防「VMax 钳位打败阻尼」极限环。

**④ 拖拽 pin（交互）**
被拖节点位置硬写为指针世界坐标，速度清零：

```
if pin.Valid:  pos_pin = pin.Pos ; v_pin = (0,0)
```

其余节点**不**被直接移动——只经弹簧/斥力被带动（这就是「整树按物理动起来」）。

### 2.3 积分（半隐式欧拉，每帧一次）

```
v += F · dt
vx *= relPhysDampX ; vy *= relPhysDampY   // 按轴阻尼（当前 0.5/0.5，D126 订档）
|v| 限幅 ≤ relPhysVMax                    // 防播种爆炸/病态输入
pos += v · dt
```

- `dt = 1.0`（固定每帧一步；**帧率相关**，见 §8 权衡）。
- 阻尼：乘性衰减 ⇒ 扰动后指数衰减到静止。D126 按用户实测「太晃」订档：横向/纵向各 0.5，
  实测真实会话树 ~40 帧/0.7s 收敛、单次轻过冲。弹簧力/树锚另加 `relPhysFMax` 限幅——
  巨幅振荡时若不限幅，弹簧加速度会每子步把速度推回 VMax 钳位，阻尼永远追不上（极限环）。

### 2.4 收敛判定（R3）

```
kin = Σ_i (vx_i² + vy_i²)
settled = kin < relSettleEps · n
```

静止即 `settled` → 帧层停帧。任何交互（拖拽 pin、rebuild）都会注入能量 → 自动唤醒。

## 3. 静息布局（rest layout）——确定性参考

物理的平衡态（弹簧把每个子拉到 `父+偏移`）即一个**确定性树形**，独立于物理过程计算：

```
restPos(root) = (0, 0)
restPos(i)    = restPos(parent) + ( restOff[i] ,  restGap[i] )
```

- `restOff`：沿用 relAssign（扇区序） + 卡片宽 pitch（`max(卡宽, relRestLen) + relSlotGapDp`）
  的兄弟并排逻辑（D126 修订：角度比例取位后按顺序 **dodge** 保最小槽距——等规模兄弟
  原来会被压到 0.35×pitch，卡片在静息态就相叠，接触推力把平衡态推离静息布局 ~20dp）。
- `restGap[i]`：纵向层距，默认 `relRowGap`；用户手动摆放后由 `adoptSlot` 改写（持久槽位）。
- 用途：
  1. **fitView / recenterTree 的树盒**——按静息树形算外接盒（当前物理位形会动，不适合做视场基准）。
  2. 物理播完的归宿（接触推力下有界偏移：真实会话树 0.0dp；密集卡片树有已知重叠，见 D126 限制）。
- 性质（测试锚点）：有界、可复现、树形（`restY(子) = restY(父) + restGap` ⇒ 静态层序单调；
  手动摆放后层距钳在 0.75~2.0 × 72 内，「子恒在父之下」不变）、兄弟按 restOff 有序。

## 4. 生命周期与帧循环

### 4.1 状态机（取代现状的三态 + 入场 lerp）

```
┌───────────┐   rebuild（开窗/数据变更/预算）
│  SEEDED   │──────────────► 新布局播种（§4.2），settled=false
└─────┬─────┘
      │ 每帧 step(dt, pin)（帧循环经 InvalidateCmd 续帧）
      ▼
  PHYSICS ──► 动能 < 阈值 ──► 静止（停帧；任何交互唤醒）
```

- **没有「入场动画」概念**：开窗/重排后的「长出来」就是物理从播种位形到静息位形的
  运动过程本身。
- **没有「按下即打断」**：用户操作（zoom/pan/悬停/右键）不扰动位形，物理照常；
  拖拽 = 加 pin，与物理叠加。

### 4.2 播种（rebuild 时）

| 场景 | 播种 | 效果 |
|---|---|---|
| **开窗首帧 / 全新图** | 全部向**静息盒心**收缩 `relSeedShrink`(0.6) + 按节点确定性小抖动 | 物理从盒心**向外展开**（D126 修订：向根点收缩会让深链盒心起点离锚点几千 dp、展开被树锚猛拽 ⇒ 平移过冲 4268dp + 极限环；向盒心收缩 ⇒ 播种盒心 = 锚点，展开是纯扩张） |
| **数据变更（新消息）** | **按节点 ID 保留旧位置**；新节点从父当前位置播种 | 增量形态变化——新节点物理「蹦出来」，整树几乎不重排（现场友好） |
| **预算/会话切换** | 同「数据变更」（保留交集 ID 位置） | 平滑过渡 |

- 位置保留实现：rebuild 前按全局节点 ID 记下旧 `sol.Pos`；新布局逐节点查表，
  查不到（新节点）→ 用父位置。
- 播种后速度 `v = 0`，`settled = false` → 物理立即开跑。

### 4.3 帧层（relGraph.tickLayout 重构）

```
tickLayout():
  if lay == nil: return false
  if lay.settled && dragNode < 0: return false      // 静止即停（R3）
  if dragNode >= 0:
      decay dragGrabX/Y（跟手，~120ms 归零，沿用 D122）
      pin = { Index: dragNode, Pos: dragPinWorld() }
  lay.step(relDt, pin)
  sol = lay.solution()
  more = !lay.settled || (dragNode>=0 && 偏移未衰减完)
  return more
```

- `dragPinWorld` / `grabAt` / `relGrabSlop` 原样沿用（按下抓取 + 抓取点衰减跟手）。
- 帧预算 `relaxLeft` 保留为安全兜底（病态输入下触顶即停）。

### 4.4 视场
- `fitView`（开窗首帧）：按 **静息树盒** 取最小 zoom 对准盒心（fit 下限 = 标签可读
  下限 0.75，沿用 D122）；仍装不下则锚点居中。
- `recenterTree`（拖后松手）：保持 zoom，静息树盒对准视口。
- 数据变更不重置 zoom/视场（沿用 D122）。

## 5. 拖拽交互（用户最关心的「整树动起来」）

流程（沿用 D121/D122 的抓手判定与跟手，物理部分替换）：

1. **按下**：`grabNode = hitTestSlop(press, relGrabSlop)`（宽半径补抓）；记抓取偏移。
2. **越过 slop 拖动**：`dragNode = grabNode`；每帧 `pin = dragPinWorld()`（指针世界坐标
   − 衰减中的偏移），`step(dt, pin)`。
   - 被拖节点钉在指针下（速度清零）。
- **其余节点**：子被弹簧拉（子树拖着走）、邻居被接触推力推开、再传给它们的邻居——
     **整棵树出现物理波纹**，带惯性（速度不瞬间为零），松手后一两下轻摆即收敛。
3. **松手/取消**：撤 pin；**把当前位置采纳为静息槽位**（`adoptSlot`：`restOff`/`restGap` 写回、子树递归重算、槽位按消息 ID 持久）——否则弹簧的零内力平衡态就是旧静息布局，被拖节点会被拉回旧形状（用户实测「拖完还是回到一个固定的形状」）。随后物理按新形状收敛 → 静止；`fitPending` 把树拉回视野（recenter，树太大时走 fit 回退的视图跟随）。
4. **点击 /goto**：slop 内原地释放 = 点击（判定不变）。

## 6. 性能

- **物理步进**：接触推力 O(n²)（排除祖先-后代对；链/主干实际 O(n)）、弹簧 O(n)。200 节点实测 0.23ms/帧（12 子步，0 allocs，已固化基准 `relmap_anim_bench_test.go`）。
- **绘制**：200 节点已固化基准（D126 复测：物理仿真帧 0.77ms、拖拽帧 0.94ms、纯物理步进 0.23ms）。
- **合计 < 1ms/帧**，60fps 预算 16.67ms 的 ~5%，裕量充足。
- **R3**：静止即停帧（§4.3），不空转；续帧预算耗尽 = 认账收敛（`relSettleFrames` 硬顶，防病态输入无限续帧）。

## 7. 测试策略

### 7.1 静息布局（纯函数）
- 树形：`restY(子)=restY(父)+72`；根 (0,0)；有界；可复现（两次构造逐点相等）。
- 兄弟有序（restOff 单调）；卡片不深压（静息态穿透 ≤ 卡宽 × relCardPenetrationMax）。
- 输入守卫（空/多根/父越界/自环/环）——沿用现有。

### 7.2 物理步进
- **settles**：无 pin 跑 N 步后 `settled`，位形有界、无 NaN。
- **可复现**：同输入同种子 → 逐帧轨迹一致。
- **阻尼降能**：动能总体下降、终态静止（重解一致）。
- **pin 传播**：钉住某节点并移动 → 邻居位移 > 0（整树响应）；松手后收敛回静息附近。
- **卡片不深压**：物理播完后同层穿透有界。

### 7.3 帧层
- 开窗：从盒心收缩播种 → 若干帧内位形在动 → 静止；期间所有节点在视口内（fit 用静息盒；
  树太大 fit 回退时走**视图跟随锚点**，当前消息始终居中）。
- 数据变更：旧位置保留（未变节点坐标几乎不动）、新节点从父位弹出；**手动摆放的槽位按
  消息 ID 恢复**（adoptSlot 持久，rebuild 不冲掉）。
- 拖拽：被拖节点跟手、邻居被带动、视场不平移；松手后**采纳当前位置**、按新形状收敛即停。
- 点击 /goto、菜单、预算——沿用（不回归）。

### 7.4 性能基准（固化）
- `BenchmarkRelmapPhysStep200`（纯物理步进）、`BenchmarkRelmapPhysFrame200` /
  `BenchmarkRelmapDragFrame200`（帧，数值随物理版复测；D126 复测：步进 0.23ms、
  物理帧 0.77ms、拖拽帧 0.94ms @200 节点）。
- 门禁：`go test -race`、gofmt、vet。

## 8. 权衡 / 待你拍板的点

1. **静止即停 vs 永久微动**（最关键）：
   - 推荐：**阻尼收敛到静止后停帧**（R3 不烧资源；「全程都能动」= 任何时刻可被扰动、
     会按物理回应，不是永远在抖）。
   - 备选：加极小的持续环境扰动（树永远微微呼吸）——代价：永不收敛、持续烧帧，
     且 200 节点永久占用一帧预算。**不推荐**。
2. **2D 自由 vs 层带约束**：
   - 推荐：**2D 自由**（真正「按物理规律动」，拖拽会荡起来）。代价：动态中孩子可能
     短暂荡到父上方（**层序只在静息时严格成立**），树偶尔交叉。
   - 备选：y 用软弹簧拉向层带（`k_layer` 轻约束）——更可读但垂直方向不太「物理」。
3. **帧率相关**：
   - 推荐：固定 `dt=1/帧`（与现状同口径，简单）。120fps 屏上物理快一倍（收敛 ~0.5s）。
   - 备选：`dt` 用 `gtx.Now` 真实时间（帧率无关）——阻尼需指数化 `damp^(dt·60)`，
     系数更复杂。**可后置**。
4. **参数档位**（§2 系数）**已由 spike + 用户两轮实测订档**（D126）：目标观感 = 拖拽跟手、
   松手轻摆一两下、静止树形干净不缠。最终值：弹簧按轴 1.0/2.0、阻尼按轴 0.5/0.5、
   树锚 0.03、每帧 12 子步、力限幅 `relPhysFMax=12`、`relSettleFrames=900`；
   实测真实会话树 0.7s 收敛。「约 10s 慢摆」试验档（软弹簧 0.012 + 阻尼 0.982）已被用户
   实测否决（「太晃」），且软弹簧会卡局部极小、顶离槽位——见 D126。
