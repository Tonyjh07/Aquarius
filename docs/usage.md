# 参考手册

> **第一次使用请先看[用户手册](guide.md)**——那本按「怎么用起来」写，不要求懂编程；
> 本文是逐条命令与参数的速查，写给要抠细节的人。
>
> 本文与当前实现对齐；**设计上有冲突以 [DESIGN.md](../DESIGN.md) 为准**。配置字段见 [configuration.md](configuration.md)，数据与备份见 [storage.md](storage.md)。

## 快速上手

```bash
go build ./cmd/aquarius
./aquarius.exe        # 首次运行生成根指针 + profiles/default/config.json 模板后退出
# 填 model.providers（base_url / models / api_key），设置密钥环境变量，重新运行
```

默认 **GUI 悬浮球**（`ui.kind=gui`：托盘常驻、Alt+A 呼出、不进任务栏）。
输入栏左侧的**回形针**可选文件随消息发出（文件框支持多选，一条消息最多 8 个，见
[用户手册](guide.md) 第 6 节）。
**输入框为空时，右侧圆钮是语音键**（麦克风图标）：点一下开始录音、再点一下结束，
转写文字回填输入框（不自动发送，可先改错字）；录音中圆钮变停止键。有输入时恢复为
发送键。语音在设置窗「语音」页配置（识别/合成各自的服务与模型、音色与风格、试听；
服务与模型改动保存后重启生效），也可直接改 `audio.asr` / `audio.tts`
（见 [configuration.md](configuration.md)）；**识别服务未配置时保持发送键不变**（合成配没配
不影响麦克风——录完要转写，缺的是识别）。
**双击启动不弹控制台**：仅本次启动独占新建控制台（双击/资源管理器/开始菜单）
时窗口即隐，日志与启动警告不可见；需看日志（复现问题、明文 api_key 警告）请**从终端启动**。
`ui.kind=tui` 起 **TUI**：转写区 + 输入框 + 状态行（模型/权限/用量），
上下键历史、PgUp/PgDn 滚动转写、Ctrl+C 取消当前生成、committed 回答带轻 markdown 渲染；
`ui.kind=repl` 为行式 REPL（测试/e2e 后端）。TUI/repl 中直接输入文本即对话；`/help` 看命令；
`/quit`（或 `/exit`）退出。
（Ctrl+C 语义：TUI 取消本轮后保持待命；repl 取消本轮后进程随即退出。）

启动会自动恢复最近一次会话，并把该分支**模型可见的历史**（上个压缩摘要 → 最新；
没有摘要则从首条消息起）回放进转写区，附一条 `已恢复会话 <标题> (<id>)，回放 n 条历史`
提示——persona 配置快照与摘要水位之上的旧内容不回放。

## 命令参考

| 命令 | 说明 |
|---|---|
| `/new [标题]` | 新建会话（立即落盘；首条消息后默认标题自动改为消息摘要） |
| `/list` | 列出会话：最新在前，当前会话行首标 `*`，`N条` 为消息数（不含 Root） |
| `/title` | 无参：显示当前标题；有参：改写标题并即时落盘（会话元数据，不动消息树） |
| `/goto <id>` | 回溯到任意节点并把它设为新起点（支持唯一前缀；输入会话 ID 或其前缀回到根） |
| `/edit <id> [--keep\|--copy] [--part N] [--attach <路径>]... [--drop N]... [--drop-all] [<文本>]` | 修改某节点：缺省 **Fresh** 另起同级新节点（原分支保留）；`--keep`（须紧跟 id）**Carry** 把该节点的后续历史边转移过来；`--copy`（须紧跟 id）**Clone** 深拷贝后续历史为独立副本（新旧两份互不影响）；`--part N` 只替换第 N 个正文分片（0 起，思考/工具/附件分片原样保留——GUI 气泡编辑自动携带）；`--attach <路径>` 追加附件（可重复，按序接在末尾，须绝对路径）、`--drop N` 移除第 N 个附件（0 起，按附件在消息里的出现序）、`--drop-all` 移除全部附件——三者只影响新修订出的节点，不动附件库，且只对用户消息开放；带附件操作时文本可省 = 只改附件，但改完至少留一段文字或一个附件；修订后清屏回放新路径；修订**用户消息**（Fresh）即重新生成回答（编辑即重发）；Carry/Clone 与助手/系统消息修订一律不触发生成 |
| `/regen <id>` | 重新生成（id 可为用户或助手消息）：取上游最近一条用户消息重发并生成新回答——已有回答时另起同级新节点（旧回答保留为历史分支，分叉条可切回）；尚无回答时直接在其上生成 |
| `/respond <id>` | 从所选节点**继续生成一条响应**（id 可为任意**非根**节点，含人格/系统/工具节点）：把它设为起点后跑一轮，发往模型的就是「水位 → 该节点」这段上下文；新回答作为该节点的子节点，已有子节点时开一条新分支（旧分支保留）。会话根不可作为起点 |
| `/inject [--source <名>] [--no-trigger] <文本>` | 手动注入一条上下文：入树为**注入节点**，默认起一轮响应（`--no-trigger` 只塞进上下文、等下一次输入）；`--source` 标注来源（任意名，缺省按「手动」处理，任务来源默认起响应、工具/插件来源默认只补上下文；它只改展示与触发默认，**不影响这条内容被当作可信宿主事实**——那是你亲手写的）。工具/MCP 走同一内核入口，不经此命令 |
| `/branch [id]` | 分支视图：该节点自身 + **同级分叉**（新旧版本对比）+ **下级**，Root 显示顶层消息；缺省当前起点 |
| `/rm <id>` | 删除节点及其后代（Root 不可删；二次确认后执行，剪枝即落盘，落盘失败自动回滚；`-yes` 启动可跳过确认）。被删子树里若有别的版本的「修订自」记录，那条溯源会一并清掉——确认句会先把件数讲明 |
| `/compact` | 触发上下文压缩（见下节） |
| `/permission [等级]` | 无参：当前等级 + 免确认矩阵 + 特权目录；有参：切换等级并写回 config，工具链路即时生效 |
| `/unattended [on\|off]` | 无人值守：**越界操作当场拒绝并说明**，不再弹确认等人（权限等级本身不变）；无参 = 切换，有参 = 显式设置；写回 config `permissions.unattended` 并热生效。与 `-yes` 相反——那个是自动放行，两者同时出现时 `-yes` 优先 |
| `/memory [会话id]` | 用系统编辑器打开记忆文件（缺省全局 `memories.md`，带参会话记忆；保存后下次读取生效） |
| `/usage` | 用量查看：当前上下文占用（精确/≈估算）、上轮实测 prompt/completion、会话累计 |
| `/jobs [list\|logs <id> [行数]\|kill <id>]` | 后台任务管理：缺省 `list`；`logs` 取末尾行（缺省 50）；`kill` 终止（连同子进程）。任务由模型经 `job_start` 启动，ID 支持唯一前缀 |
| `/watch [list\|stop <id>]` | 观察器：模型声明的定时观察（看一条命令的输出、一个文件、一个网页，命中什么就回报）。缺省 `list` 看它在盯什么、已查几次、什么时候结束；`stop` 叫停。声明由模型经 `watch_start` 发起，用户不在这里写探针 |
| `/mic [秒数]` | 录一段话（缺省 60 秒，上限由服务端体积反推）→ 转写 → 作为一条用户输入提交；录音中再触发会提示正在录音。需配好 `audio.asr`，非 Windows 平台明确报不支持 |
| `/model [name]` | 无参：当前 provider + 当前模型 + **生效能力**（工具/思考/图片，整条降级链取与，并指名哪一环在拉低）+ **上下文预算**（生效值，以及是被模型窗口还是全局上限压住的）+ 降级链逐环 + 可用清单（单价标注）；有参：先写回 config `model.name` 再 Agent 内热切换（同 `/permission` 模式），下一轮即生效；provider/端点/降级链/窗口改设置窗或 config（重启生效） |
| `/model probe [模型名]` | 实测某模型到底收不收得下工具调用、思考、图片：三条最小请求、逐项三态结论（支持/不支持/无结论，附依据与耗时用量）。图片那一项给一张纯色图让它说颜色——说对才算支持。**只把判定明确的几位写回** `models[].caps`（无结论不动现有声明），重启后生效。省略模型名 = 当前模型；探测是真请求、真花钱，故只在手动发起时跑 |
| `/think [on\|off]` | 无参：原生思考开关（缺省开）；有参：切换并写回 config `model.think`。**总开关**：off 时 `reasoning_effort` 与 `enable_thinking` 一律不发（覆盖 `/effort`）；当前链的模型未声明思考能力时同样不发 |
| `/effort [级别]` | 无参：当前 `reasoning_effort` 档位；有参：`minimal\|low\|medium\|high\|off`（off 清除）写回 config `model.reasoning_effort`。是否真发由 `/think` 决定；on 且未设档 = 不发（交服务端默认） |
| `/plugin [list\|enable <name>\|disable <name>]` | MCP 插件管理：list 显示状态/来源/传输/能力授权/调用统计/重启与报因，并列出可用动态命令；enable 走 capability 首用确认并写回 config；disable 即时摘除其工具与命令 |
| `/skill [list\|<名字>]` | 技能：无参或 `list` 列出已安装的技能（名字、一句说明、来自哪个目录、加载失败的条目与原因）；带名字 = 把该技能的 `SKILL.md` 正文注入上下文（**不触发新一轮**，下一句话就能用上），并显示技能目录路径 |
| `/skill install <路径\|链接>` | 安装技能：单个 `SKILL.md`、技能文件夹、`.zip` 压缩包或 GitHub 链接（`…#分支`）；先校验再落位，同名不覆盖 |
| `/skill remove <名字>` | 卸载安装副本（只删 `<配置目录>/skills/<名字>`，二次确认；来自其它技能目录的同名技能不受影响） |
| `/skill update <名字\|all>` | 更新：git 来源拉取、压缩包来源重新下载，然后覆盖副本（**会覆盖本地改动**）；不带名字 = 更新全部可更新项，复制来源需重新导入 |
| `/export [--format <名字>] [--path <文件>] [--all]` | 导出会话。缺省只导**当前**会话。`aqx`（缺省格式）= **无损**，附件字节一并装进一个文件，可原样导回，**一份归档能装多个会话**（`--all` 把整库写进一份备份）；`chatgpt` = 树形互通格式，含全部分支，能被认这套的工具直接读；`openai` / `sillytavern` = 线性文本，**只导当前上下文那条链**（分叉不在其中）。后三种是有损的：思考、工具调用与附件不会带出去，回执会逐项列出丢了什么；它们**一次只能装一个会话**，与 `--all` 一起用会直接报错。不带 `--path` 时落在 profile 的 `exports` 目录，文件名取自会话标题（`--all` 用固定名）；同名不覆盖（自动加 `-2`） |
| `/import [--pick <序号>] <文件>` | 导入外部会话：按扩展名与文件内容自动认 `aqx`、ChatGPT 导出、Open WebUI 导出、SillyTavern 聊天记录、OpenAI 消息数组。**落成新会话**，不覆盖既有会话。`aqx` 里有多份会话时，不带 `--pick` 全部导入；`--pick 1` 或 `--pick 1,3` 只导清单里那几项（序号从 1 起，越界会报错并列出清单）。界面上的「导入」会先弹一个勾选面板让你挑，默认全勾。文件损坏或超出上限会直接报错，不做「尽力修复」；**本版之前的单会话旧归档不再支持**，导入时会提示重新导出 |
| `/character [list]` | 角色卡：列出已导入的卡（显示名、slug、来源、开场数、备用问候数、世界书条数、导入警告） |
| `/character show <slug>` | 看一张卡的详情：创作者、版本、标签、有没有头像、哪些内容保留但没启用；卡正文含 HTML 时提示界面按纯文本显示 |
| `/character import <路径>` | 导入角色卡：PNG（元数据藏在图里）、纯 JSON、或 `.charx` 压缩包。原卡原样留档；同名不覆盖（先 `remove` 再导入）；回执分四类说清世界书、资产、不执行的机制与只展示字段 |
| `/character start <slug> [序号]` | 用这张卡开一个**新会话**：卡的角色设定接在你的默认人格之后，示例对话作为可被压缩挤掉的上下文，开场白作为第一条 assistant 消息；不带序号 = 第一条开场白，带 N = 第 N 条备用问候 |
| `/character remove <slug>` | 删除这张卡（二次确认）。用过它的会话照常能打开，只是头像回到默认 |
| `/delegate [list]` | 外部代理清单：名字、命令行、版本、能不能用（PATH 上探没探到）、不可用原因、哪个是缺省。**转交本身不在这里发起**——那是模型经 `delegate` 工具做的事，你只负责批准或拒绝 |
| `/mcp:<server>:<prompt> [args]` | MCP prompts 动态命令（随插件启停注册/注销，`/plugin list` 查看可用项）；渲染结果作为用户消息走完整一轮 |
| `/quit` `/exit` | 退出（`/exit` 为别名） |
| `/help` | 命令帮助 |

> 节点 ID 支持唯一前缀匹配；自身、同级与下级节点 ID 可用 `/branch` 查看（逐层下钻可达任意深度）。
> "修改"永不改写旧消息：Fresh 另起节点、Carry 边转移（后代本身不变），会话树始终保持不可变。

## 内置工具（模型自行调用）

模型可在回答过程中调用工具；**执行前一律过 ToolRunner**：权限矩阵判定 → 矩阵外逐次
`[y/N]` 确认（`-yes` 全免）→ 单次超时（`limits.tool_timeout_sec` 缺省，任何调用可带
保留参数 `timeout_sec`（整数 1–3600）逐次覆盖，允许高于 config）→ 结果按
`limits.tool_output_chars` 裁剪。拒绝/超时/工具自身失败都以 `OK=false` 回填给模型，
不中断对话；**基础设施故障**（确认器缺失/报错、Ctrl+C 取消）则快速中止本轮，不空转。

| 工具 | 说明 | Risk |
|---|---|---|
| `memory_list` / `memory_read` / `memory_search` | 记忆索引/读取/关键词检索（只见全局 + 当前会话两份） | Safe |
| `memory_write` | 写入记忆（`mode=append` 缺省 / `overwrite`；strict 下路径格外需确认） | Confirm |
| `file_read` / `file_list` / `file_search` | 读文件（可分页：`offset`/`limit`，带行号与续读标注；图片直接给模型看，需当前降级链上的模型都声明了 `vision` 能力）/ 列目录 / 按文件名递归搜索（**绝对路径**，读全盘免确认） | Safe |
| `file_edit` | 精确子串替换（`old_string` 须唯一，`replace_all` 放开；保留原换行与 BOM） | Confirm |
| `file_write` / `file_delete` | 覆盖写 / 删除（写按权限矩阵路径格判定） | Confirm |
| `think` | 显式整理思路（no-op，内容随调用入树）——**默认不列给模型**，`model.think_tool: true` 启用 | Safe |
| `sleep` | 等待 N 秒（停顿或等后台任务；Ctrl+C 可中断；1–3600s，超缺省超时须在该次调用上带 `timeout_sec`） | Safe |
| `context_compact` | 触发上下文压缩（等价 `/compact`，自我管理上下文） | Safe |
| `term_exec` | 同步执行终端命令行（`cmd /c` / `sh -c`；超时统一控制，输出保头尾截断；输出自动转 UTF-8，无须 `chcp`；执行类看工具列） | Confirm |
| `job_start` | 启动后台任务（独立进程，日志落盘 `profiles/<name>/jobs/<id>.log`，不随对话取消；**任务结束时自动汇报**，无需反复查） | Confirm |
| `job_wait` | 等后台任务结束并直接拿结果（状态/退出码/耗时/日志尾部）：编译、跑测试这类确定会结束的任务用它，不必等下一轮汇报。不传 `timeout_sec` 表示一直等（随时可中断）；等超时只回「还在跑」，任务继续 | Safe |
| `job_list` / `job_status` / `job_logs` / `job_kill` | 后台任务管理（列表/状态/日志尾部/终止） | Safe |
| `watch_start` | 声明一条观察器：`kind`（command/file/http）+ `target` + `match`（正则，省略 = 输出有变化）+ `notify`（match 报一次即结束 / change 每次重新命中都报）+ `interval_sec`（5–3600，缺省 30，固定间隔）+ `max_checks` / `deadline_sec`。**命中才回报**，未命中不打扰；等 CI、日志里出现某行、文件出现用它 | Confirm |
| `watch_list` / `watch_stop` | 观察器列表 / 停止 | Safe |
| `window_list` | 列出可抓取的顶层窗口（标题、程序名、屏幕矩形、是否前台，按 z 序自顶向下）；`handle` 传给 `screen_capture` | Safe |
| `screen_capture` | 截屏给模型看：`target` = `screen`（整个虚拟桌面）或窗口 `handle`（抓客户区，**被遮挡、非顶层的窗口也抓得到**；最小化窗口经系统合成器的预览取整窗，不还原窗口、不抢焦点；纯 GPU 自绘窗口取不到会明确报因）；打开着的菜单/下拉会合进主图。PNG 进附件库并随结果内联（长边超 1600 会缩小）。仅 **Windows** 支持；当前链上的模型未声明图片能力时调用即报因 | Confirm |
| `ask_user` | 向你提问（一次 1–4 题，每题最多 9 个选项，可多选，也可以自己输入）：GUI 在输入栏原地展开问答面板，命令行前端逐题打印编号选单。**不吃默认工具超时**——想多久都行；无人值守或 `-yes` 时立即回「用户不在」，不阻塞轮次 | Safe |
| `web_search` | 联网搜索：`query`（1–128 字符，支持 `site:` / `"短语"` / `-词` / `lang:zh,en` / `after:2025-01-01` 等算符）+ `count`（1–20）+ `freshness`（day/week/month/year）。按 `web.search.providers` 的顺序换家，回填里注明这次实际用了哪家、之前哪家失败了 | Safe |
| `web_fetch` | 抓一个网页并转成 Markdown（`url` + `max_chars` 500–20000）：导航与脚本被剔除，长文按预算截断并提示还能继续读。本地抓取遵守 `robots.txt`，拒绝内网/回环目标 | Safe |
| `skill` | 载入一个已安装技能：常驻清单里只有名字与一句说明；调用后拿到该技能 `SKILL.md` 的正文 + 技能目录绝对路径。需要读 `references/` 或跑 `scripts/` 时用 `file_read` / `term_exec` 自己深入 | Safe |
| `delegate` | 把一件复杂任务**整个交给**另一个代理程序（外部 ACP 代理，见下节）：`task` = 任务描述、`agent` = 用哪个（省略用缺省）、`workdir` = 它的起点目录（省略家目录）。它自己起进程、自己用工具，回来后只有**报告 + 一行摘要**（工具调用数、改动文件、耗时、停止原因）。**不吃默认工具超时**；按 ESC 取消会把取消请求转达给它。一次只允许进行一个 | Confirm |

联网能力由配置决定，两件工具**始终注册**（没配就调用会明确告诉你缺哪一段）：

- 抓取开箱可用：模板默认带本地实现（纯 Go，无需密钥）。
- 搜索需要先配一家提供商，例如在 profile 的 `config.json` 里写
  `"web": { "search": { "providers": [ { "kind": "deepseek" } ] } }`——`deepseek` 借
  `model.providers` 里同名 provider 的地址与密钥；也可以用 `{ "kind": "brave", "key": "secret:AQUARIUS_BRAVE_API_KEY" }`。
  两家的顺序就是优先级，前面那家挂了会自动换后面那家（详见 [configuration.md](configuration.md)）。
- GUI 用户不必手写这段：设置窗「联网」页可以增删、调序、换类型，密钥框留空 = 沿用原值。

## 上下文压缩（三轨特色功能）

会话树不可变，压缩不删历史——它生成一条 **system 摘要节点**作为"水位"：此后装配
`[persona] + [最新摘要] + [摘要之后]`，摘要之上（persona 除外）的历史不再发给模型。
被裁掉的原文仍在树上，随时可回溯（`/goto` 回到压缩节点之前即可"撤销"压缩效果）。

- **手动轨（已可用）**：`/compact`
  - 摘要之上没有新历史 → 提示"无需压缩"，不花生成费用；
  - 成功 → `已压缩 N 条历史 → 1 条摘要（in=X out=Y tokens）`；
  - 摘要按**英文结构化模板**生成（Objective/Requirements/Decisions/Work State/
    Next Move/Relevant Files/Important Context，对任意 agent 通用接手），
    已有旧摘要时合并更新（新历史优先）；输出缺小节带提醒重试一次，仍不合格按失败处理；
  - 取消/失败 → 会话树无损，可重试。
  - 多次压缩链式吸收：新摘要把旧摘要一并吞掉，上下文永远只带最新一条。
- **自动轨**：每轮生成前按**三级 token 计数链**估算上下文
  （①已发生的服务端实测 usage 自校准 → ②适配器本地 tokenizer 精确计数，
  配置 `model.tokenizer` 即启用 → ③通用估算 ASCII÷4 / CJK÷1.5 / 其他÷2），
  达 `limits.compact_threshold`（默认 0.7 × `max_context_tokens`）自动压缩——
  每次 Run（单条输入触发的整轮工具循环）至多一次；失败回退"最旧裁剪"
  （保人格与最近、丢中间，`[notice]` 提示省略条数，绝不留下孤立 tool 消息）。
- **自触发轨**：模型经 `context_compact` 工具（Safe）自我管理上下文。

persona（人格）恒回传：它是会话首节点（system 角色），源自 config 的 `system_prompt`
（空则用内置默认），可用 `/edit <persona-id> --keep <文本>` 改写（Carry 保留整棵对话树）。

## MCP 插件

Tier-2 = 任意 MCP server（stdio 或 streamable HTTP 双传输，用官方 go-sdk）：

- **声明**在 config `mcpServers.<name>`（stdio：`command`/`args`/`env`；http：`url`/`headers`，
  值可用 `secret:<环境变量名>` 引用）或 `profiles/<name>/plugins/<m>/plugin.json`；
  **启停与授权状态**在 config `plugins.<name>`（同名声明以 config 为准）。
- **授权**：声明的 `capabilities` 首次启用逐项 `[y/N]` 确认，通过即写入 `granted`；
  未配置确认器时 fail-closed 不启动；`risk=confirm` 的工具仍逐次确认（不随授权放行）。
- **工具**：`tools/list` 注册为 `mcp:<server>:<tool>`，与内置工具同权过 ToolRunner 权限矩阵；
  出站到模型时换成端点安全别名 `mcp_<server>_<tool>`（严格端点不接受冒号），会话树与日志仍是冒号形态；
  server 崩溃自动重启（1s/2s/4s 退避、限 3 次），超限置 `crashed`；重启与调用统计见 `/plugin`。
- **resources** 只读并入记忆索引与 `memory_*` 读取面（写/删仍走自有记忆）；
  **prompts** 暴露为 `/mcp:<server>:<prompt>` 动态命令。
- `/plugin list` 看状态，`enable`/`disable` 即时启停（写回 config，重启沿用）。

## 技能

技能 = 一个目录 + 一个 `SKILL.md`（YAML frontmatter 写 `name` 与 `description`，下面是给模型的
指令）。它和「系统提示词」不一样：**只有你要用的时候才进上下文**——平时模型只看到名字和一句说明，
真命中才把整篇正文读进来，所以装十来个技能也不会把每轮的上下文撑大。

- **放哪**：`<profile>/skills/<名字>/SKILL.md` 就生效（开箱可用）；也可以在自己的
  `config.json` 里加 `skills.dirs`（绝对路径、按顺序）指向别处的技能目录，比如你用 git 管的仓库。
  同名技能先声明者生效。
- **写什么**：`name` 必须与目录名一致（小写字母、数字、连字符，≤64 字符），`description` 一句
  话写清「这个技能做什么、什么时候该用」——模型就是靠这一句决定要不要载入的。
  目录里还可以放 `scripts/`（脚本）、`references/`（参考资料）、`assets/`（模板），模型载入技能后
  会拿到目录路径，需要时自己读、自己跑。**脚本不会自动执行**，跑脚本一样要过权限确认。
- **怎么用**：直接说需求即可，模型会自己判断该载入哪个技能；也可以 `/skill` 看装了哪些、
  `/skill <名字>` 手动把某个技能载入上下文（不触发回答，下一句话就能用上）。
- **坏技能不会拖垮启动**：缺字段、名字不合规、YAML 写坏的技能会被跳过，`/skill list` 里能看到
  哪一条没加载上、为什么。

## 角色卡

角色卡是 RP 生态里现成的角色设定包（常见的 TavernCard）：一张 PNG、一个 JSON 或一个 `.charx`
压缩包里装着名字、外观与性格描述、场景、开场白、示例对话，通常还有头像。本版**只读导入**：
把卡读进来、投影成一次会话的开头，不改卡、不导出卡。

- **怎么进来**：`/character import <路径>`（GUI 在设置窗「角色」页点「导入」）。三种容器都认：
  PNG（卡数据藏在图的文本块里）、纯 JSON、`.charx`（ZIP）。新版卡（V3）优先于同名的旧块。
- **原卡原样留档**：`<配置目录>/characters/<slug>/` 下的 `card.json` 是**导入时那份字节**，
  `.charx` 还会整包留一份。所以卡里我们不认识、这一版不用的东西（世界书的非常驻条目、
  表情、背景、正则脚本、作者写的扩展字段）都没有丢，只是暂时不生效。
- **开始对话**：`/character start <slug> [序号]`。卡的**角色设定接在你自己的默认人格之后**——
  你的人设不会被卡悄悄替换（想让卡的 `system_prompt` 接管主提示，把
  `characters.prefer_system_prompt` 打开；即使打开，平台与沙盒路径这类运行环境信息仍然保留）。
  示例对话作为一条可被压缩挤掉的上下文塞在人格之后，开场白作为第一条 assistant 消息；
  带序号可选第 N 条备用问候。
- **常驻世界书默认会注入**：卡里标成「常驻」（`constant`）且没被作者禁用的条目，会整段接在
  人格里——不少卡把人设整个写在这些条目里，不注入就只剩个开场白。代价是它每轮都占上下文，
  且不会随压缩被消化；嫌占地方就关掉 `characters.inject_constant_book` 再重开一次会话。
  其余世界书条目仍要逐条按键匹配才会生效，那是后续版本的事。
- **只展示、不进上下文**：创作者留言（`creator_notes`）、标签、创作者、版本号都只在
  `/character show` 里看。作者留言尤其不会被喂给模型——它是写给你看的。
- **保留但不执行**：卡里的正则脚本、扩展脚本一类的机制与表情/背景/语音资产本版都不执行，
  导入回执会逐类说清哪样读了、哪样没读。卡正文里有 HTML 时界面按纯文本显示（标签会原样出现），
  导入时会提示。
- **同名不覆盖**：再导入同一张卡会得到一个新 slug；要换版本先 `/character remove` 旧的。
- **删卡不影响历史**：`/character remove` 只删卡目录，用过它的会话照常打开，只是头像回默认。
- **卡能被模型执行吗**：不能。导入不授予任何工具权限、不执行脚本、不读卡里引用的本地路径与
  网址；卡里的文字就是文字。

## 外部代理转交

有些活不适合由 Aquarius 的工具循环一件件拼出来——跨很多文件的重构、要反复试错的构建修复、
长链路的排查。这类任务可以**整个交给另一个代理程序**：它有自己的工具循环和自己的判断，我们只
负责把任务递过去、把报告收回来。协议是 ACP（Agent Client Protocol），走它的人已经不少，
所以装上就能接。

- **怎么配**：`config.json` 的 `delegate.agents` 里写一条，形状和 MCP server 一样——
  `command`、`args`、`env`（值可用 `secret:<名>`）。**不发预设**：各家代理的命令名与启动参数
  由它们自己定，我们抄一份只会过时。启动时按 `PATH` 探一下，探得到的才标「可用」；探不到的
  仍列在清单里并写明原因（「装了但 PATH 上找不到」比「清单里没这条」好查）。
- **怎么看**：`/delegate list`（GUI 在设置窗「外部代理」页）。看得到名字、命令行、版本、
  能不能用、哪个是缺省。
- **怎么触发**：你正常提要求，模型自己判断这活该转交，然后调 `delegate` 工具——它会先弹确认。
  **转交不该由你手写任务描述**：模型的活是拆任务，你的活是批准或拒绝。
- **回来什么**：树里只多一个工具结果——**它的最终报告 + 一行摘要**（工具调用几次、改了哪些
  文件、跑了多久、怎么停的：正常结束 / 到输出上限 / 到轮次上限 / 它主动拒绝 / 被取消）。
  它中间那几十次工具调用、思考、计划表**不进你的对话**：那是它的过程，塞进来会挤占你自己的
  上下文，也会让压缩摘要分不清哪段是谁的历史。
- **追问要重述背景**：每次转交都是**全新会话**，进程跑完就关，它不记得上一次。想让同一件活
  接着做，把上文带上再说一遍。
- **改动的文件**：摘要里的「改了哪些文件」来自它自己的汇报，可能不全——有的代理只报一部分。
  想确认就自己看，或在要求里明确让它列全。

### 权限边界（请务必读完再批准）

**转交出去之后，那个程序有它自己的文件与命令访问。** 我们只接得住它**愿意问**的那部分：

- 它动手前如果反过来征求同意（协议里有这一条），我们把它转成你的确认框，你选「允许」或
  「拒绝」；拒绝会如实传给它。你填的理由只留在我们这边的提示与日志里——协议的应答没有理由
  字段，它只知道被拒。
- 它不问你的时候，它读写哪些路径、跑什么命令由它自己的策略决定。你给的 `workdir` 是它的
  **起点目录，不是围栏**——它不受我们的权限等级矩阵约束。
- 所以批准一次转交 = **批准那个程序在它自己判断下动手**。确认框会写明这一点。
- **无人值守**时转交一律被拒（没人能批准的事不该悄悄放行），轮次不阻塞。
- 取消（ESC / 停止键）会把取消请求转达给它；它若在规定时间内没停下来，进程会被强制结束。
  已经交出的报告照常保留，不当成失败。

## 权限等级

四档：`read-only` / `strict`（默认）/ `permissive` / `full-access`。`profiles/<name>/sandbox`
是 Agent 的特权目录；等级决定**哪些操作免确认**，矩阵外的操作一律逐次确认。
逐格规则（哪个目录可写、哪些工具调用免确认、`network`/`secret` 怎么算）见
[配置参考的 permissions 段](configuration.md#permissions)——那里是唯一详表，本文不重复。

- `/permission <等级>` 切换并写回 config，工具链路即时生效（每次执行现读等级）。
- **无人值守**（`/unattended`、球/托盘菜单、设置窗「常规」→「权限」）：走开一会儿时用。
  权限等级一字不改，只是模型发起的越界调用不再弹确认，而是当场拒绝并回填原因（没人能批准 /
  别重试 / 在允许范围内继续 / 把待批事项列出来），模型会改道，轮次不会被卡住。你自己键入的
  命令确认（`/rm`、删会话）与插件授权照常询问；`ask_user` 直接回「用户不在」。状态行会常驻
  「无人值守」标记。它与 `-yes` 方向相反（自动放行），两者同时配置时 `-yes` 优先并启动告警。

## 常见问题

- **启动报"发现旧格式会话"**：很早的原型数据不兼容，按报因点名的
  ID 删除 `profiles/<name>/conversations/<id>.json`（含 `.bak`）后重试，详见 [storage.md](storage.md)。
- **启动警告"api_key 为明文"**：明文密钥直接写在 config.json 里，任何能读
  该文件的进程都可取用——到设置窗「模型服务」页（或欢迎窗）重填一次即转入本机加密密钥库，
  config 里只留 `secret:<名>` 引用；也可手工改成 `"api_key": "secret:名"` 再配同名环境变量。
  该项留空也会自动回落默认引用（两处都取不到时才报错退出）。
- **密钥库**：真实值存 `<profile>/secrets.bin`（本机加密；Windows 用系统账户加密，其它平台用
  同目录 `secrets.key`）。取用顺序 = **先查库、再查同名环境变量**。设置窗「密钥库」页可列出/
  新增/覆盖/删除任意名字（列表只显示名字与尾 4 位掩码）。**目前不提供「一键收进存量」的界面入口**：
  以前直填在 config 里的明文密钥，请在「模型服务」页重填一次（会自动转入密钥库、config 只留
  `secret:<名>` 引用），或手工把 `api_key` 改成 `"secret:名"` 再配同名环境变量。**备份/同步/换机拷走的
  `secrets.bin` 解不开**，这是预期行为；那种情况下启动只打一行警告、继续用同名环境变量兜底，不会阻断。
- **思考链路**：`/think off` 关闭原生思考（不发 `reasoning_effort`/`enable_thinking`）；
  `/effort high` 只存档位、配合 `/think on` 才发送；`reasoning_effort` 非法值启动即报因
  （`minimal|low|medium|high`）；服务端不认的参数会被自动剥离并记入
  `model.unsupported_params`（要恢复发送就从该数组删掉对应字段）。
  思考过程**随节点入树**（`PartThinking` 分片，实时暗块与启动回放都看得到）；实时阶段正文
  一直铺开，**定稿后折叠成一行「▸ 已思考 N 秒」**，点一下这一行展开正文、再点收起（开合只
  影响显示，不改变会话树）；
  是否**回传给提供商**由 config `model.echo_thinking` 控制——**键缺失即回传**（DeepSeek 等
  兼容端点带 `tools` 时强制，缺失会 400），设为 `false` 可关；回传走 assistant 消息的
  `reasoning_content` 字段，服务端不认时自动剥离并记入 `model.unsupported_params`。
- **启动报未知权限等级**：`permissions.level` 只接受
  `read-only|strict|permissive|full-access`。
- **`ui.kind` 报未支持**：只接受 `gui`（默认，悬浮球）、`tui` 与 `repl`（行式，测试/e2e 后端）。
- **想换模型/端点**：模型名 `/model`（热切）或 config `model.name`；provider/端点改
  `model.providers`（设置窗「模型服务」页可全量编辑：协议 / 端点 / 密钥池 / 模型列表，含连通性
  测试与逐模型「探测能力」；切到该页会自动拉一遍各家服务端的模型清单，新拉到的行默认未启用，
  勾上「启用」再把这次变更应用出去，重启生效）；或用
  `-model`/`-base-url` flag、`AQUARIUS_MODEL`/`AQUARIUS_BASE_URL` 环境变量临时覆盖。
