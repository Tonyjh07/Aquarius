## 版本路线

> 已发布版本的落地记录在 [roadmap.md](roadmap.md)，这里只排还没做的版本。

| 版本 | 主题 | 内容 | 状态 |
|---|---|---|---|
| v0.5.0 | 多语言界面 + 规范化日志 + 首次运行引导 | 三条主线：**界面 i18n**（`zh` / `en`，代码面已收口，剩 `en` 人工视觉走查）、**规范化日志**（五段式运行日志，收尾批 L2 / L3 / L4）、**欢迎窗重构成五页引导**（O1–O5）。外部代理那一线整体移入 v0.6.0（见下）。语音前处理与说话人仍在 backlog，不占这一版 | 收口中（i18n 与日志的底座已落地，见 [roadmap.md](roadmap.md) 的 v0.5.0 行；逐日排期见下方「v0.5.0 发版排期」） |
| v0.6.0 | 外部代理：设置窗直接配 ACP + 申报 `fs` / `terminal` | 三件由浅入深：先把代理**配得明白**（A1，设置窗里增删改、根集、权限、连通性），再让读写**经我们手**（A2），最后让命令**由我们执行**（A3，含前置验证）。语音前处理与说话人仍在 backlog | 规划中 |

**方向**：v0.5.0 的三条主线是同一件事的三个面——都在**收口**而不是加功能：多语言把界面文案收进
一处取词口，日志把输出收进一处写出点，引导把「第一次启动该问的几件事」收进一个向导，而不是让
用户在设置窗十几个页签里自己找。都是**先文档后代码**：i18n 动的是 tui/gui 与命令面共同的取词口，
日志动的是全仓唯一的输出口，引导动的是配置的启动不变量（见 O4）。

**外部代理这一线为什么整条移出 v0.5.0**（2026-11-03 拍板）：它还要加上一件原先没排的事——
**设置窗里直接配 ACP**（增删代理、命令行、根集、权限、连通性），不再只靠手写 `config.json`。
申报面（`fs` / `terminal`）的口径取决于「配置里到底能写什么」，两块拆开做等于把同一套字段口径
写两遍；而且申报 `terminal` 的前置验证要真拿几个代理跑一遍，塞进本周只会变成「写了没验过的协议面」。

建包拆包与语音前处理仍留在 backlog：前者实测买不到什么（D234），后者等 VAD 的端口改动拍板。

## 多语言界面（v0.5.0，第一条主线）

> 多语言是项目**规范化**的里程碑之一，不是翻译功能。这条界线先拍死：一旦滑到「把用户内容也
> 翻了」，就是另一个产品。边界与批次见下，别处不再复述。

**要什么**：界面文案按语言取一套，先 `zh` / `en`；启动时按 `ui.lang` + 系统语言选，认不出回落 `zh`。

**边界**：

- **进**：界面控件与提示、命令 `Desc` / `Usage`、`/help` 与命令浮层、设置窗、空态与确认句、
  进用户视野的报错与 `stderr` 行。
- **不进**：文档正文（`docs/` 仍是中文单套，另议）、进入模型上下文的字符串（已全英文，与新规则
  无关）、开发者调试日志、会话与用户内容（不翻译、不检测语言）。
- **表外唯一一处**：用户自己在设置窗填的输入框占位文字（D279，已落地）。它是用户内容进了界面，
  不随 `ui.lang` 变；取词口只负责「没填时用哪一条内置文案」。

**形状**（已定，口径见 D275 与 contracts §7.8）：一个取词口 `internal/i18n`——`zh` / `en` 两张
**Go 表**（26 对区域文件、2410 条 key）、`{name}` 具名占位符、缺键回落 `zh`；`ui.lang` 三态
（`auto` / `zh` / `en`），**启动定一次**，设置窗常规页可改（重启生效）。扫描锁五把已全部落地：
`lock_test.go` 四把（字面量、缺键、孤儿 key、拼接前缀两侧闭环）+ `lock_expect_test.go` 的
`TestNoCJKExpectations`（测试期望值跟 key 走，白名单 `testDataLiterals`）。i18n 的代码面已收口，
本节只剩人工走查（见验收末条）。

**验收**：

- `ui.lang=en` 起一遍、`go test ./...` 在 `AQUARIUS_UI_LANG=en` 下也跑一遍，两边都绿；从欢迎页到
  设置窗、`/help`、生成中插话、确认与报错无一句中文残留；切回 `zh` 与今天逐字一致（同一套 key，
  不是两份手写文案）。
- 两条扫描为空，白名单每一条都写得出理由：生产侧出口字面量（I7，已落地）、测试侧期望值字面量（I6）。
- 占位文字三态各对一次：内置（`zh` / `en` 各一句）、自定义（两语言下都是同一句）、清空回落。
- 真窗口视觉走查（人工，进行中）：窄窗 + 200% 字号下看发条、气泡、设置行与状态行；按
  `TestEnExpansionReport` 的清单（`-v` 打印）继续看，修掉的记 [roadmap.md](roadmap.md)。

**风险**：

- 出口扫描与期望值扫描都是白名单：新写一处可见文案若走了清单外的写法（自绘、拼字符串），
  锁一样看不见；清单要随新增的文本出口一起长。
- 占位文字是表外唯一一处「用户内容进界面」；以后若做界面文案检索 / 术语表，这一条要显式绕开。
- 文案表一旦成为第二份「事实来源」，就容易和界面行为脱节：key 只增不改语义，删改要跟着代码走。

## 规范化日志（v0.5.0，第二条主线）

> 与多语言同属「规范化」，不是可观测性平台：不引 metrics、不接 OTel、不做采样。一条日志只回答
> 五件事——什么时候、多重、哪个子系统、出了什么事、当场怎么处置。字段口径这一节定死，别处不复述。

**要什么**：全仓只有**一处**输出口。现在仍有 23 行直接写 `w.stderr`（`cmd/aquarius` 的
`assemble_ports.go` 15 / `bootstrap_profile.go` 3 / `plugins.go` 2 / `welcome.go` 1 / `web.go` 1 /
`main.go` 1），另有 24 处带中文格式串的 `Logf` / `logf`（`internal/plugin` 13 / `acpgate` 4 /
`outputtts` 3 / `skillfs` 2 / `characterfs` 2），这些行没时间、没级别、没上下文。

**字段**（已定，五段固定顺序）：

| 位 | 内容 | 形态 |
|---|---|---|
| 时间 | 本地时区到毫秒 | `2026-11-02 18:20:31.482` |
| 级别 | `debug` / `info` / `warn` / `error` | 定宽对齐 |
| 上下文 | 子系统标识：`boot` `attach` `llm` `job` `delegate` `plugin` `skill` `session` `perm` `ui` `web` | 英文标识，**不是文案**，不进 i18n |
| 事件描述 | 发生了什么，具名占位符 `{name}` | i18n key（`log.<ctx>.<what>`） |
| 行动 | **已做的处置**（跳过 / 回落 / 重试 / 已改存 / 延后），不是给用户的指令 | i18n key（`log.act.*`，按动作收敛复用） |

- 文本形态：`18:20:31.482 WARN  attach   附件超过 20MB，已跳过  → 已跳过该文件，其余照常`。
- JSON 形态（`--log-format json`）：字段同名；`ctx` / `event` / `action` 给 **key**（不随语言变，
  贴日志排障时读得懂），另给 `msg` / `act` 的译文与 `kv`。
- 事件与行动**分两条 key**：同一件事在不同处置下是两条日志（跳过 vs 回落），别把处置写进事件句里。

**边界**：

- **进**：启动与装配、运行期事件、适配器内部失败（`Logf` 那一族）。
- **不进**：`audit.log`（JSONL 调用审计，机器面，字段是另一套）与 `jobs/<id>.log`（外部进程自己
  写的原始输出，不是我们的行）；REPL/TUI 的回执与状态行（那是界面，已在 i18n 表里，不加时间戳、
  不带 `→`）；进模型上下文的字符串。
- `fatal` 保持原样：启动期致命错误要「一句话 + 消息框」，不是一条日志行，也不改它的措辞路径。

**落点与开关**：

- 全量写 `profiles/<p>/logs/aquarius-YYYY-MM-DD.log`（随 profile 隔离，与 `audit.log`、`jobs/`
  同一口径）；按天切、单文件超限轮转一代、保留 7 天；写失败静默（日志不得打断对话，同 audit）。
- stderr 只出 `warn` 以上，同格式单行；`debug` / `info` 只进文件。
- 级别：`--log-level` > `AQUARIUS_LOG_LEVEL` > `ui.log_level`（模板 `info`）。级别名与 `event` /
  `action` key 是三条出口共享的契约，改一处即三处一起改。
- 包 `internal/logging`：叶子层，只 import 标准库与 `internal/i18n`，并登记进 `internal/arch`
  的 `layerLogging`——理由同 `layerI18n`，不登记就落进 `layerOther` 成后门。
- **适配器不 import 日志包**（硬性规则 1 的方向）：注入回调，形状是 `port.Log(level, ctx, event,
  act, kv…)`（`internal/port/log.go`）。L2 之前那个 `Logf(format, args…)` 临时形状已在 L3 删净。

**批次**：

- **L2**（M）：`cmd/aquarius` 那 23 行收口——`assemble_ports.go`（15）、`bootstrap_profile.go`（3）、
  `plugins.go`（2）、`welcome.go` / `web.go` / `main.go` 各 1；`fatal` 与消息框不动。装配根当下把
  `w.stderr` 当默认出口（`stderrProxy`），改成「默认写日志、`warn` 以上再照旧打一行」；每行要
  判出 `ctx` 与行动位，不能只把 `Fprintf` 换成 `log.Warn`。
- ~~**L3**（M）~~（已完成 2026-11-04）：那 24 处调用逐一收口，端口换成**结构化回调**
  `port.Log(level, ctx, event, act, kv…)`，装配根 `wiring.logFrom` 接到 `logging`。`internal/plugin`
  的 `[plugin] ` 前缀由 `ctx` 位取代（`logCtx = "plugin"`），前缀不再留在文案里；`acpgate` /
  `skillfs` / `characterfs` / `outputtts` / `host` / `probe` 的字段，以及 `app` 侧
  `logf("%s", Tf(...))` 的转发壳一并换掉（`app` 那几处本来就有 key，补齐级别、上下文与行动位）。
  适配器里原先硬编码的中文句子按 `log.<ctx>.<what>` 拆成 key，`log.*.line` 占位句与
  `log.act.verbatim`、以及 `cmd.asm.char.prefix` / `cmd.asm.skill.prefix` 两个行内前缀一并删；
  原本散在 `delegate.*` / `watch.*` / `inject.*` 段的事件句归入 `log.*`。新增 `character` 上下文
  （角色卡目录）。i18n 的中文字面量锁随之撤掉对 `logf(...)` 实参的豁免。`audit`（机器面）与
  `jobproc`（原始输出落盘）排除。
- ~~**L4**（S）~~（已完成 2026-11-04）：上锁——`fmt.Fprint*(…stderr…)` 只许出现在 `logging`
  包、`fatal`、向导取消报因与 TUI 崩溃兜底（`cmd/linuxgate` / `cmd/iconify` 是开发工具、
  不进产品日志，白名单里写明了这条）；调用点的事件 key 后面必须紧跟 `log.act.*`，key 的
  上下文段必须在 `Contexts` 里登记且与调用点给的 `ctx` 一致。两把锁都在
  `internal/logging/lock_test.go`。`configuration.md` 的三个键（`ui.log_level`、
  `-log-level`、`AQUARIUS_LOG_LEVEL`，外加 `-log-format`）L2 时已补齐，本轮只核了一遍；
  `development.md` 补了「怎么看运行日志」。

**顺序**：L2 / L3 是纯搬；**L4 排在 I6 之后已无冲突**——I6 的期望值扫描锁已落地
（`internal/i18n/lock_expect_test.go`），L4 沿用它的 AST 口径（字面量定位、白名单按文件给
理由、相对路径用 `filepath.Rel`）；锁本身放在 `internal/logging`，它守的是日志出口，不是文案表。

**验收**：`--log-format json` 跑一轮含附件、语音、插件、后台任务与转交的会话——文件里每行五段齐、
`event` / `action` 是 key 不是译文；`zh` / `en` 两套文本都读得通；stderr 只有 warn 以上；GUI 双击
启动后能在 `logs/` 里找到同一次运行的完整流水；`cmd/` 下 stderr 写入口只剩白名单。

**风险**：

- **与 i18n 表抢同一行**：日志文案只追加到既有的 `internal/i18n/zh_log.go` / `en_log.go`
  （`log.act.*` 与事件两族），不另开表文件、不动 `mergeTables` 注册行；两边同时改同一行是这类
  并行唯一的冲突面。
- **行动位退化成自由文本**：一句一条地写就成了第二份文案表。口径是按**动作**收敛（五六个动作覆盖
  全部日志），事件只说自己那件事。
- **两条渲染路径要同源**：文本与 JSON 从同一份字段结构渲染，别各拼一遍；时间格式、级别名、key 名
  是三者共享的契约。
- **用户提示混在流水里**：现有 stderr 行有的其实是界面提示（「语音播报不可用」在设置窗也要看得见）。
  分流按「用户是否需要知道、是否需要立刻知道」判：判错要么让流水混进 UI 文案，要么让界面上那句

## 外部代理：设置窗直接配 ACP + 申报能力（v0.6.0，整条主线）

> 2026-11-03 拍板：代理不再只靠手写 `config.json` 配，设置窗要能直接增删改。这条把申报面也一并
> 带出来——申报 `fs` / `terminal` 的口径取决于「配置里到底能写什么」，两块拆开做等于把同一套
> 字段口径写两遍，所以同版、按 A1 → A2 → A3 由浅入深。
> 「转接的任务并行」仍不在这一线——它随后台化一起进主线（D261）。

### A1 设置窗直接配 ACP（M，先做）

**现状**：D270 的外部代理页只有 启停 / 设缺省 / 改命令行 三件事。`args` 与 `env` 被压在
「一行命令、按空白切分」里，`workdir`、根集、连通性没有入口；加一条要手写 JSON，删一条只能
改文件（`configuration.md` 里现在写着「页面只改不删」）。

**要什么**：

- **条目级增删改**：新增（名字 + 命令 + 参数）、删除、改名；重名与缺名按解析期同一条校验拦在
  界面里，不留给下次启动吃 fatal。
- **字段级可编辑**：`args`（一行一个）、`env`（键值表，值可写 `secret:<名>`，给出已存密钥的
  候选）、`workdir`、`enabled`、`default`。
- **连通性**：一条「测试连接」——起进程、`initialize` 握手、回显 agent info 与它申报的能力；
  失败要分开「命令不在 PATH 上」与「握手失败」两类，现在只探得到前者的消息。
- **根集与越界策略**：写在本页、读在 A2，本批只落输入与落盘，不落执行侧。

**落点**：`uigui.DelegateAdmin` 扩方法（`Add` / `Remove` / `Rename` / `SetEnv` / `SetWorkdir` /
`Probe`）→ `cmd/aquarius/delegateadmin.go`；写盘沿用 `persistConfig` 的泛键改写。
**先验一件**：现有改写器能不能**增删数组元素**——`SetCommandLine` 只改已知条目，空值靠
`delete(m, "args")`。数组级增删若不支持，本批第一笔就是把它补上，这是 A1 的地基。

**风险**：

- 写回 `config.json` 会重排键序、丢手写注释；编辑面从「一行命令」扩到「整条目」后这件事会更
  显眼。要么在本页写明「保存会重写配置文件」，要么把写盘收窄到只改 `delegate.agents` 那一段。
- 页面显示的是**配置 + 现算 PATH**，不是运行中的转交管理器（D270 口径），改动一律「重启生效」；
  「测试连接」会**真起一个进程**，必须有超时与「正在连接」态，不能卡住 UI。
- `env` 里的 `secret:<名>` 是解析期的事，界面只负责写文本，别在设置窗里解析或缓存密钥。

### A2 申报 `fs`（M）

**要什么**：把「它改了哪些文件」从**它自称**变成**我们经手**。现在 `Changed` 取的是它
`tool_call_update` 里报的路径——它不报就漏、它报错就脏；这一份清单是报告里最容易被当成事实
的一段。申报 `fs.readTextFile` / `fs.writeTextFile` 之后读写都过我们的进程，这是唯一能拿到
可靠改动清单的路径。

**义务**（协议的 MUST/SHOULD，逐条都要落）：

- `fs/write_text_file` 文件不存在**必须创建**；父目录不存在要不要建协议没说，按「建」处理
  并在用户文档写死。
- 路径按**会话根集**（`cwd` + 可选的 `additionalDirectories`）**逐段比对、fail closed**；
  越界不静默写，转 `Confirmer`。
- 写**执行控制类文件**（版本控制钩子、代理与编辑器设置、MCP 配置）单独问一次——协议点名这几类。
- `fs/read_text_file` 的 `line` / `limit` 是 **1 基行号切片**，不是字节偏移。

**顺带能收的**：`Changed` 从「它报的」换成「我们写过的 + 它报的」两份来源取并集，摘要行里
区分「经手 N 个 / 自称 M 个」——不比现在更假。

### A3 申报 `terminal`（L，前置验证通过才做）

**要什么**：命令由**我们**执行，于是能拦、能限、能杀，输出能进报告。

**先验证再承诺**：申报之后主流代理是否真的改走 `terminal/*`。能力申报只是给出一条**可选**
路径——它照旧自己起 shell 的话，我们只是多开一条攻击面、风险一点没减。**判据**：拿两三个代理
各跑一次，报文里真的出现 `terminal/create` 才算数；一次都不出现就登记不做，理由写进决策记录。

**义务**：五个方法（`create` / `output` / `wait_for_exit` / `kill` / `release`）；`outputByteLimit`
要有界缓冲，超限**从头截断且必须落在字符边界**；`kill` 之后终端仍可用（还要能取最终输出与
退出码），`release` 才释放；命令策略要匹配 `command` + `args` + `env` 三者，不是只看命令名。

**一条不能含糊的**：协议原文——「The root set declares the session's scope. **It confines shell
commands only when a sandbox enforces it**」。我们没有沙箱：申报等于我们自己按当前用户身份执行
任意命令，根集只是我们用来拒绝的判据，不是内核围栏。用户文档里要跟「两条执行路径并存」一起
讲清：走我们的那条能审，它自己起的那条永远看不见。

## 测试并行与 `-race` 墙钟（backlog，未排期）

> **现状**（2026-11-03 实测，16 核）：`go test ./...` 41 秒；`go test -race ./...` **316 秒**
> （7.7 倍）。包级并行 `go test` 自己就按包打满了，墙钟由**最大包**决定——`internal/adapter/uigui`
> 一家 281.7 秒 = 全量的 89%。所以能压的只剩包内，而全仓 `t.Parallel()` 目前是 **0**。
>
> **收益已量过**（临时 worktree 里用脚本批量插 `t.Parallel()`，随插随跑；原仓库除下面那两处锁修复外
> 未改。uigui 那一行是一次带失败的运行——失败是下条前置里的时序脆弱用例，不影响墙钟口径）：

| 包 | 现在（`-race`） | 允许包内并行 | 倍数 |
|---|---|---|---|
| `jobproc` | 28.8s | 6.6s | 4.4× |
| `uigui`（683 个顶层测试 / 96 个测试文件） | 281.7s | 53.8s | 5.2× |
| 全量 `-race` | 316s | 60 秒量级（上限转到下一个最大包 `cmd/aquarius` 25.6s） | — |

> **第一道坎已经拆掉**：批量并行第一次跑就顶出 21 个 `-race` 失败，栈全指向两个无锁包级缓存——
> `monoFace`（每窗各建一份主题，写它的是设置窗、读它的是主窗的帧循环）与 logo 的缓存档位
> （`logoOnce` 只守解码，`logoPx`/`logoOp`/`logoOK` 裸读写）。两者都是生产 bug 而非测试噪音，
> 已在 `7c2ccb9` 修掉（`codeFont()`/`setCodeFont()` + RWMutex、`logoMu`）；同一套并行跑法再跑，
> **0 个 DATA RACE**。剩下的是机械活加一处脆弱测试。

**剩下三件，按成本排：**

1. **先让 `TestImageViewFrame` 可并行**（S）：`imgthumb_test.go` 用 `select … default` 非阻塞取解码
   结果，隐含「`frame()` 返回时解码已完成」。并行后必偶发（实验里稳定复现一次）。改成 `select` +
   `time.After` 超时等待即可，改动只在测试文件。
2. **`i18n.Use` 的用例不加并行**（零成本）：`lang_test.go`、`placeholder_test.go`、
   `settings_nav_test.go` 切的是进程级语言槽。Go 的语义正好帮忙——带 `t.Parallel()` 的测试会等
   所有非并行顶层测试跑完才统一开跑，所以这几处**保持不加**就够了，不用改产品代码。
3. **逐包落地并压测**（M）：一批一个包，每批 `-race -count=5` 起步确认无偶发。

**顺序**：`jobproc`（零改造、4.4×、已实测全绿）→ 其余小包（`cmd/aquarius` 25.6s、`acpgate` 8.9s、
`storejson`、`llm` …）→ `uigui`（按测试文件分批，一批一笔提交）。

**重启判据**：现在不做是因为收益不值这份工——单笔提交只跑相关包，全量 `-race` 一天几轮；而
683 个测试要逐个判断「它确实不与同包他人共享状态」，审的成本高于把 281 秒压到 54 秒。值得重启的

## 语音前处理与说话人（backlog，未排期）

> 三项同属「能力扩张」，排在 backlog 的中后段。共同前提是一件事：
> 现在的语音链路是**整段式**——`port.Recorder.Record` 一次返回完整 WAV，`micwin` 单缓冲采集、
> 默认 60 秒、硬顶 4 分钟（`maxRecordBytes`），`ingestmic.Listen` 拿整段去转写。只要还在这个形状里，
> VAD 无处落脚（它要的是逐帧判定），唤醒词与声纹也没有连续的输入可喂。
> 所以次序是 **VAD 先做**：它顺手把采集口改成流式分帧，后两项才有前置条件。

### VAD（语音活动检测）：先做，S~M

**做法**：不自己写。`github.com/vithnilica/go-silerovad` 是 Silero VAD v6.2.1 的纯 Go 实现
（MIT，权重内嵌约 1.2MB）——无 cgo、无 onnxruntime、无外部模型文件，只依赖标准库，完全符合
单二进制口径。`Stream` 接受 8–192kHz 任意采样率并自带多相重采样；32ms 一块的推理约 0.95ms
（单核约 3%），实时无压力。分段默认值沿用上游：阈值 0.5、负阈值低 0.15、`MinSilence` 100ms、
`SpeechPad` 30ms、`MinSpeech` 250ms。备选 `zserge/govad`（v5 半精度、只吃 16kHz、低维护）
仅作兜底，不选。

**前置改动（这条是主要工作量）**：`port.Recorder` 从「一次返回整段 WAV」改成流式产出帧，
`micwin` 由单缓冲改为连续缓冲 + 定长 32ms 读出，`ingestmic.Listen` 由「录完 → 入库 → 转写」变成
「边录边判：检到语音开始才缓冲，静音超过 `MinSilence` 就切段，逐段入库转写」。断句结果仍是
独立的 WAV 片段，附件与转写链路不动。改动涉及端口定义，**先改 [contracts.md](contracts.md) §5.6 再改码**。

**验收**：对着麦克风说三句、中间各停 1 秒，得到三段独立转写而不是一整条；
纯静音 30 秒不产生任何附件、不发起转写；`/mic` 与 GUI 语音键行为一致；端口改动的契约测试覆盖
「用户主动停止时已录到的音频照常返回」（现行语义，不能丢）。

**风险**：`Detector`/`Stream`/`Segmenter` 都非并发安全，必须一个采集流一个实例（权重只读共享，
约 1.2MB）；要求 Go 1.26+（本机满足）但**没有任何版本 tag**，只能依赖伪版本，升级得盯 commit；
仓库目前 2 个提交、0 star，属于「写得好但没人用」的新项目，接进来要把它当自有代码对待，
别指望上游及时修。模型来自 Silero VAD v6.2.1（MIT），作者请求在使用处标注引用，一并写进
`THIRD-PARTY-NOTICES.md`。

### 唤醒词：待定，暂不排版本

**现状是两条路都不通**，原因不在代码而在分发许可与运行时：

1. **openWakeWord** 代码 Apache-2.0，但**预训练模型是 CC BY-NC-SA 4.0**（非商业 + 传染），
   不能随二进制分发，也不能让用户「下载即用」地替我们绕过。
2. **microWakeWord**（OHF-Voice）代码与 `esphome/micro-wake-word-models` 都是 Apache-2.0，
   模型层面干净，但它要 TFLite Micro 的 INT8 运行时；Go 侧只找到 cgo 的 `mattn/go-tflite`，
   没有纯 Go 的 INT8 TFLite 解释器。为唤醒词开 cgo 会破坏「无 cgo、单二进制」的交付口径。

**两条未解路径**（要先拍板走哪条，拍完再进本文排期）：

- **自训 Apache-2.0 模型**：用开放语料训 microWakeWord 形状的 INT8 模型，许可证由我们决定；
  代价是要补一个纯 Go 的 INT8 推理内核（只覆盖该模型用到的算子），属于「为一项功能写一个引擎」。
- **外置 openWakeWord 服务**：不进程内跑，唤醒词交给用户自己起的服务，内核只做 HTTP 客户端。
  与下文声纹同一形状，代价是「单二进制开箱可用」降级为「要另起一个服务」。

不进入任何版本的边界，也不列验收——**先定路径**。

### 声纹识别：外置服务 + 协议位，M

**模型选型**：3D-Speaker 的 CAM++（`speech_campplus_sv_zh_en_16k-common_advanced`，代码
Apache-2.0），80 维 fbank 输入、192 维 embedding，ONNX 体积 fp32 27MB / fp16 14MB / int8 8.2MB，
中文场景可用。WeSpeaker 代码同为 Apache-2.0，但 resnet34-voxceleb 等**权重**是 CC-BY-4.0，
若走 WeSpeaker 必须逐模型核对许可证。

**为什么不进程内跑**：三个纯 Go ONNX 引擎都不够格当生产依赖——`Kazuhito00/onnx-purego-interpreter`
自述比 ONNX Runtime 慢 5–30 倍且「不作为 ORT 替代」，`AdvancedClimateSystems/gonnx` 只到 opset 13
且 2024 年后未发版，`oramasearch/onnx-go` 走 Gorgonia、自述实验性；`shota3506/onnxruntime-purego`
虽免 cgo 但通过 purego 调原生共享库，仍需分发 `.so`/`.dll`。所以**结论是外置服务 + HTTP 适配器**，
不在进程里塞引擎。

**形状**：照既有语音端口的做法办——调用方（`app`）定义一个小端口（如「音频 → 说话人标签」），
配置面按**协议位**新增一个 kind（如 `audio.speaker.kind`，`campplus` / `http` 两档），适配器把 WAV
发给服务、换回 embedding 或「是否本人」的判定。配置取值仍沿用 `base_url` / `api_key` 显式字段优先、
缺的才借 `model.providers` 的既有顺序（D222）；分派仍是白名单 + 越界即报错（D223）。
**先补 [contracts.md](contracts.md) §5.6 与决策记录再动码。**

**用途**（决定验收怎么写，需产品上先定）：说话人分离（多段转写标注是谁）与「只认我的声音」的
入口门。**验收**取决于选哪个：分离版看同一段两人对话能否标对；门禁版看他人声音是否被拒且
误拒率可接受。

### 与本仓工程准则的关系

- 三项都不得引入工作区/文件索引之类的抽象，也不得让 VAD 或声纹进模型上下文——判定结果只作为
  「这段音频是谁 / 从哪开始」的元信息，附在附件或转写上。
- `silerovad` 的权重内嵌进二进制，许可证与体积都要进 `THIRD-PARTY-NOTICES.md`。
- 唤醒词若最终选外置服务，`README` 的用户面措辞要写「需要额外跑一个服务」，不写内部编号。
