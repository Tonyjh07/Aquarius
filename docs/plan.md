## 决策策略：四态放行 + 模型辅助（v0.7.0，整条主线）

> 2026-11-07 拍板方向：① 每个工具一条放行策略，四态、用户主动设、覆盖权限矩阵；
> ② 那一档「模型辅助」由一个决策模型代替用户点确认；③ 设置这些策略最自然的时刻就是弹框那一刻，
> 所以确认框本身要给两个即时动作——直选档位、以后都允许（D280/D281/D282）。
>
> **前置已具备**：v0.6.0 带出了 `fs` / `terminal` 两条真实确认路径，从那一版起「用户批了什么、
> 拒了什么」才有记录可当标注集。本版开工前不改这两条确认路径的任何口径。

### 要什么

现在的确认路径是二元的：矩阵判 `Allow` 免确认，判 `Ask` 弹框（D22，矩阵外无出口）。这留下
三个没人管的问题——**问得太多的那部分没人替你挡**（同一件事问第十遍，人就开始盲点同意），
**不该问的那部分没法预先声明**（矩阵只有四档全局等级，改一档是动全局），**想放宽的那一刻不在
设置页**（真实的授权时刻是弹框那一下，让人先关掉弹框再去设置页，等于让用户做两次）。

### 四态各自的落点

| 档 | 落在哪 | 现有机制 |
|---|---|---|
| 禁用 | **装配层**：不把工具定义传给模型 | 就是 `tools.disabled` 的语义（`toolrun` 按 `Specs` 过滤） |
| 询问 | 判定层：矩阵判 `Ask`，弹框 | 现状 |
| 模型辅助 | 判定层：先问决策模型，拿不准再弹框 | 新增 |
| 自动放行 | 判定层：跳过确认 | 矩阵判 `Allow` 时已经是这个行为 |

**禁用不是运行期拒绝**，所以 `perm.Decision` **不加 `Deny` 出口**，D22 的「矩阵外一律 ask」
不破。禁用省下的是模型那一次白试——工具定义不在，模型根本不会去调这个工具。

**优先级：用户显式 > 矩阵 > 缺省 ask。** 显式覆盖两个方向都允许：矩阵判 `Allow` 的可以改成
「询问」（收紧），判 `Ask` 的可以改成「自动放行」（放宽）——两者都是用户亲手点的，与切换
`permissions.level` 是同一级别的授权，不是程序替人做决定。

**模型辅助只作用于矩阵判 `Ask` 的那一格。** 用户明说「不许」的地方模型不参与（本版没有运行期
deny，「不许」的形态只有「禁用」，也就是模型看不见这个工具）。

**只存例外，不存全表。** 配置里默认是空的，用户改了哪一条才落一条 `{来源, 工具, 档}`；设置窗
显示的是「偏离矩阵的清单」，不是 N×M 的格子。整张表一屏放不下时，用户只会去看默认值。

**作用域两维：来源 × 工具。** 来源 = `toolrun`（本地模型调工具）/ `acpgate`（外部代理请求）。
只用工具一维的话，「外部代理一律问、本地工具自动放行」这条最常用的组合表达不出来——两条线在
「写文件」上撞车。

**执行类工具（`term_exec` / `job_start`）开放自动放行，但界面标红 + 二次确认。** 命令内容是
模型现编的，按工具放行等于给一个 shell。它比 `full-access` 窄，但那个是全局面板、有明确的心理
预期，单条策略是会被忘掉的。

**一条不可覆盖的硬名单**（代码常量，不进配置、界面上不可调）：版本控制钩子、代理与编辑器设置、
MCP 配置、密钥目录、系统目录。即便该工具设成自动放行，命中硬名单也照问或照拒。这是唯一一处
策略表说了不算的地方。

### 确认框里的即时授权

真实的授权时刻是弹框那一下。让人先关掉弹框、再去设置页翻到那张表，等于要求用户做两次，所以确认框
本身要给两个动作（D282）：

- **🔑 从「升一档」改成直选档位**，且双向（升降同一处）。选完 **runner 按新档位重判本次**，
  不是 UI 自己决定放行：UI 只上报「选了哪档」，结论由 `perm` 算，两套界面不各写一遍矩阵。
  判 `Allow` 就过、判 `Ask` 就回到确认态（这一次仍要明确回答）、明确不允许就当场拒。
- **「以后都允许」**，写进上面那张表：执行类落到工具级，文件类**收窄到该文件所在目录**
  （`file_write` 一步跳到全盘可写，是从「这个文件」跨到「任何文件」）。落配置、跨重启，
  设置页的偏离清单是撤销入口；**同时落一条审计**——这是确认疲劳最容易发生的一刻。
- 硬名单照样拦；TUI 不同步（确认态仍是是/否，需要时用 `/permission`）。
- 依赖策略表，所以只能在策略表之后落地，中间不能提前放出来。

### 模型辅助怎么接

- **端口**：`port.Decider`。喂结构化 state（来源、工具、操作、目标、风险、外部代理那侧的任务
  首 80 字），三题一次问完：`should_allow`（noul）、`risk`（score 三档）、`needs_human`（noul）。
  一次调用拿三个数，串三次调用是浪费。
- **实现**：`internal/adapter/decide/`，System One 协议写一份同时覆盖 Jev 与 Clef（同 schema，
  换端点换模型）。第一家验 **Clef-flash**（9B、官方中位 38.8 ms、$0.038/M 输入、权重 Apache 2.0）。
- **接到哪**：`port.Confirmer` 的装饰器，`acpgate` 与 `toolrun` 都不出现 `if gate != nil`。
- **三档开关** `off | shadow | on`：`off` 与现在完全一致；`shadow` **只记录不改行为**；`on` 才
  按阈值分流。
- **阈值分流**：`p > auto` 放行、`review < p ≤ auto` 交回原来的 `Confirmer`（问用户）、
  `p ≤ review` 直接拒并记一条 note。两个阈值是我们按「误放行的代价」定的，不是模型给的。
- **失败即上交**：超时（1.5 s）、未配置、解析不出、模型报错，一律交给 base 问用户，绝不默认放行。
- **审计**：每次判定落一条 `{model, verdict, p, threshold, latency}`。门禁批的要能和「用户批的」
  分开读——混在一起这个功能就白做了。
- **缓存**：本轮按 `(来源, 操作, 目标)` 命中不重审。一次转交里同一个路径会被问很多遍。

### 共同地基（先做这一笔）

把 `port.Confirmer.Confirm(ctx, prompt string)` 换成带结构体的请求
（`Origin` / `Tool` / `Op` / `Target` / `Risk` / `Task` / `Prompt`），`Confirmer` 实现认 `Prompt`
保持向后兼容。四态查表与模型判定都读结构体，不必再从一句中文里反解出「它要干什么」。

### 提交拆分

1. `feat(port): give the confirmer a structured request` —— 地基，行为不变
2. `feat(perm): keep per-tool overrides beside the matrix` —— 只存例外的策略表 + 判定 + 单测
3. `feat(ui): show only the tools that deviate from the matrix` —— 设置页、执行类标红与二次确认
4. `feat(ui): pick a level in the confirm bubble instead of stepping up` —— 🔑 改直选 + runner 重判（D282 上半）
5. `feat(ui): let the confirm bubble widen the policy` —— 「以后都允许」+ 审计（D282 下半，依赖第 2 笔）
6. `feat(decide): ask a decision model before troubling the user` —— 端口 + 装饰器 + 三档开关 + 审计
7. `feat(decide): talk the System One protocol so Jev and Clef both fit`
8. `docs: record the policy precedence and what it cannot override`

### 验证

- **单测**：优先级两个方向（矩阵 `Allow` → 询问、矩阵 `Ask` → 自动放行）；禁用不出现在 `Specs`；
  命中硬名单时自动放行失效；装饰器三档阈值；失败/超时/未配置一律交 base。
- **单测（即时授权）**：选档位后三种结局（判 `Allow` 放行 / 判 `Ask` 回到确认态 / 明确不许当场拒）；
  「以后都允许」写入的范围（执行类工具级、文件类目录级）；没有策略表时退化为一次放行不报错。
- **集成**：假 `Decider` 跑完整条；`shadow` 模式下行为与 `off` **逐条对拍一致**（这是影子模式
  唯一能自证的地方）。
- **真实**：`Clef-flash`（或任一 Jev-like 端点）的连通性与延迟实测。**先测网络再谈接入**——官方
  38.8 ms 是厂商边缘到边缘，我们这边要加 RTT。
- **手验**：设置窗只看偏离项；执行类自动放行的标红与二次确认；确认胶囊从三钮变四钮后的行高、
  tooltip 与窄窗下的排布（§15.2 那套几何要重看一遍）。

### 待定

- **两个阈值**（`auto` / `review`）：影子模式跑够样本后定，本文不预设。独立评测显示二值概率
  不能按 0.5 直接切（同一份数据上按训练集调阈值后 micro-F1 从 0.50 到 0.75），且零样本迁移到
  「工具调用审批」这类负载未被证明——有实测把正常工具输出判成注入、且错得最自信。
- **自托管权重**：Clef-flash 权重 Apache 2.0，数据不出本机。要不要做取决于网络实测与数据敏感度，
  另排工期。
- **`full-access` 与策略表的关系**：现在 `full-access` 短路全部确认。是保持「全局面板仍然说了算」，
  还是让策略表在 `full-access` 下也生效（例如某工具被显式设成「询问」）——要在第 2 笔前定。
- **外部代理越界读的口径**——已定（D284）：按次数问，缺省 8 次、同一路径只问一次，
  `-1` 不限、`0` 不问直接拒。本主线仍不做读的门禁，理由是拦不住（代理自己有 shell，
  读不经过我们照样能读），所以门禁的收益不在读这一侧。
- **要不要一个对称的「以后都拒绝」**：它与「禁用」是同一个机制（不传工具定义），但「以后都拒绝」
  的表述更贴近用户在弹框那一刻的想法，而且可以省掉「去设置页关掉它」这一步。反面是一排按钮里
  再挤一个，四项已经到顶。D282 落地时看实际几何再定。

### 否决

- **`perm.Decision` 加 `Deny`**。禁用已经在装配层生效，再加一个运行期拒绝出口等于把同一件事做两遍，
  还要让所有矩阵消费点各处理一个新分支。
- **四态做成 路径格 × 工具 的二维表**。表达力过剩，配置面与界面成本翻几倍。
- **默认值也落盘**。全表存进配置，用户改一次全局等级就会遇到「配置里那 20 条还是老的」。
- **门禁的放行能越过硬名单**。那等于让一个概率数去覆盖「密钥目录不许写」这条写死的规则。

## 语音前处理与说话人（backlog，未排期）

> 三项同属「能力扩张」，排在 backlog 的中后段。共同前提是一件事：
> 现在的语音流程是**整段式**——`port.Recorder.Record` 一次返回完整 WAV，`micwin` 单缓冲采集、
> 默认 60 秒、硬顶 4 分钟（`maxRecordBytes`），`ingestmic.Listen` 拿整段去转写。只要还在这个形状里，
> VAD 无处落脚（VAD 要的是逐帧判定），唤醒词与声纹也没有连续的输入可喂。
> 所以次序是 **VAD 先做**：VAD 顺手把采集口改成流式分帧，后两项才有前置条件。

## 程序化工具调用（PTC，backlog，未排期）

> 定位：模型不再逐次发工具调用，而是写一段脚本，脚本里批量调工具，中间结果不进上下文，只把
> 最终结果交回。动因是参考 DeepSeek Harness（下文 `dsh`）的 harness 形态。
>
> 2026-11-05 调研完成，**只登记不排期**：进哪个版本、以及最终的形态与语言都待拍板。本节记
> 「要做成什么样」「为什么这么选」「哪些路已排除」，重启时先照此核一遍上游有无变化。

**动因（本仓现状）**：内置工具十几个（`file_*` / `term_exec` / `job_*` / `web_*` / `memory_*` /
`screen_capture` / `delegate_*`）加 MCP 动态工具，声明每轮全发；`runTools` 是串行 for 循环，
一次工具调用等于一次完整推理往返；`limits.tool_output_chars` 默认 20000 字符，裁完照样进树、
照样进下一次请求。于是「读 30 个文件找 3 处」= 30 次往返 + 几十万字符上下文，模型真正需要的
可能只有 5 行。

### 形态：注册表的呈现模式，不是新增工具

`dsh` 的做法是 `tools: { mode: 'native' | 'ptc' }`。`native` 发全部 JSON schema；`ptc` 下发给模型
的工具列表**只有 `run_code`**，系统提示换成自动生成的 `.d.ts` SDK（每工具一行签名 + 一句说明），
模型写的是一个 **async 函数体**（可擦除 TS），`await tools.file_read({...})`，`return` 或打印
什么就回什么。

`run_code` 是**保留传输**（restriction 层删不掉），但走完整工具流水线（`pre-execute` → 守卫 →
`execute` → `post-execute` → `result`），所以权限插件能在程序**开跑之前**读到程序全文。

对本仓的直接含义：`GenerateRequest.Tools` 与提示装配已经支持这个切法，改动面比「新增一个工具」
更小，也不会出现两套调用方式并存、目录成本翻倍。

### 行业做法（七家客户端 + 两套 API）

| 客户端 | 做法 | 脚本在哪跑 |
|---|---|---|
| Codex CLI | `exec` 工具收裸 JavaScript | 全新 V8 isolate，无 Node、无文件系统、无网络 |
| Anthropic API | `code_execution_20260120` + 工具上标 `allowed_callers` | 服务端容器，REPL 跨轮持久 |
| Cloudflare Code Mode | 只给 `search()` / `execute()` 两个元工具 | Workers isolate |
| smolagents | `CodeAgent` 直接写 Python | 本地受限解释器 / E2B / Docker |
| VS Code Copilot | 不写代码，交小模型代跑 | — |
| Claude Code / Cursor | 只有 Bash/终端 + 审批模式 | 本机，OS 沙箱或分类器 |
| Cline / Roo Code | 一条消息只发一个动作 | — |

共同点：**脚本内的每次工具调用都回同一个 tool runtime**，审批与沙箱照旧（Codex 明说保证了这
点）。最后两类不算 PTC。Claude Code 至今不做 code mode，理由是已经有 `Bash`——shell 是最原始的
PTC，代价是权限只能按命令前缀粒度管。

可用的数字：Cloudflare 2500 个端点全量 schema 要 117 万 token，Code Mode 压到约 1000；Codex 社区
实测批量化后轮次少 52%、加权 token 少 27–45%，但仍按模型目录开关、默认关；Anthropic 单 cell 90 秒
墙钟上限**写进工具描述**；smolagents 代码动作比 JSON 动作步骤少 30%、复杂基准成功率高 23%，
并自述 `LocalPythonExecutor` 不是安全边界；VS Code 的 `tool_search` 省最多 20% token，执行工具限
10 次调用。

### 五条值得抄

1. **脚本内调用必须回同一 runtime**，脚本不能绕过权限矩阵——这是行业共识，不是本仓多虑。
2. **预算写进工具描述**，不只写进错误信息。90 秒、20000 字符这些数字模型看得见才会主动分批。
3. **按模型开关，不按产品开关**。成败在模型侧，所以要做成可开能力，不是默认路径。
4. **目录二段式**：要么「每工具一行 stub 进描述」（简单、有固定成本），要么 `search` + `describe`
   （能撑到几百个工具）。
5. **并行要显式教**，否则模型默认写串行循环，省下的往返又还回去。

### 三条打到原方案上

**并发**：Starlark 没有并发，而 fan-out 正是 PTC 省时间的主要来源（Codex 用 `Promise.all`、
smolagents 用 `asyncio`、Anthropic 用 `asyncio.gather`）。补救是加一个**数据驱动**的并行原语
`parallel([{tool, args}, ...])`，由 Go 宿主并发执行、按序返回——不能传闭包，`starlark.Thread`
不是并发安全的，脚本执行必须留在单线程。

**目录成本会搬家**：现在是 30 份 schema 每轮全发，改完是「1 个 `run_code` + 30 行 stub」。单看省
很多，但 `file_read` 那种两万字符量级的说明压成一行后丢细节，得配二段式 `describe`。这条要写进
验收，否则省下的 token 会以另一种形式回来。

**与 `term_exec` 的差别只有三条**：绑定（模型看得见有哪些函数、参数是什么）、权限（每次调用过
矩阵与确认）、结果（结构化而非 stdout 文本）。答不出这三条，`code_run` 就是 `term_exec` 的重复
建设。验收里要有这份对照。

### 隔离：自 re-exec 子进程

`dsh` 每个程序起一个全新 Node 进程，走与 bash 同一套 OS 沙箱，并明确否决拿 `node:vm` 当安全
机制（「语言 realm 管不住原生 API」）。本仓对应物是 `jobproc`：加一个 `aquarius --script-host`
自 re-exec，子进程里跑解释器，复用既有的超时、杀进程树与台账。这顺带解决「解释器没有内存
上限」——堆由子进程与系统兜（`dsh` 取 512 MiB），不靠解释器自觉。

`dsh` 的默认值可直接借：单程序 120 秒（含嵌套工具与审批等待，上限 600 秒）、输出 64 MiB、
并发挂起子调用 128、并行上限 10；子调用 id 形如 `<parent>:ptc:<n>`，成功回 canonical JSON，
失败在脚本里可捕获；配额 `floor(timeout/60s × 1024)` 次**尝试**（含失败与参数非法），用完就中止
整个程序；跑完先 abort 在途、排空队列再返回；失败分八类（exception / timeout / abort /
worker-exit / invalid-output / output-limit / protocol / sandbox-unavailable），一律是**结果字段**
而不是异常；返回值必须是无损 JSON，超限算失败，不截断成字符串糊过去。

### system Python 这条路：只作后备

技术上可行：临时目录写脚本 + 一个 shim，工具调用走管道或本地回环，宿主侧照旧过 `ToolRunner`。
但代价四条都实：**能力边界消失**（脚本可以 `open`、`socket`、`subprocess`，等价于「以用户身份
执行任意代码」）；**环境不确定**（本机实测 `where python` 命中五个，含 121 字节的商店存根；
`py -0` 有 3.10–3.14 四套；`python -c pass` 冷启动 564 ms）；**交付口径破**（单二进制变成「先装
Python」）；**注入风险**——PTC 最有用的场景正是不可信内容进上下文最多的场景，一条
`urllib.post(..., open("~/.aquarius/secrets.bin").read())` 就出去了，确认机制连提示的机会都没有。

若最终启用，四条约束不能少：配置里显式写解释器路径（绝不猜 PATH）、启动探版本 ≥3.10 不达标
就禁用、Risk 固定 `Confirm`、工具描述直说「以你的身份执行任意代码，不可用于处理外部内容」。

   首版能否解析、二次能否跑通；Starlark 明显落后就换 sobek，壳与 app 层不动。
3. **排在哪个版本**：v0.6.0 已发布，PTC 没进。要进 v0.7.0 就得把四态策略表那一线往后挪，
   或者只挑 PTC-1 单独成一版；不排期就继续留在本节。
