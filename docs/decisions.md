> **维护规则**
>
> 1. **先改文档再改代码**：新决策在此追加，编号只增不改、不重排；被取代者保留原文并在 **状态**
>    指向取代者。
> 2. **新增默认一行**：新决策先在索引表写一行结论，够格（见第 3 条）才在「记录」里展开正文。
>    正文写**决策**与**为什么**（动机、约束、用户拍掉什么），不抄实现步骤——实现看代码与 [contracts.md](contracts.md)。
> 3. **够格** = 影响公共 API、数据模型、协议、插件机制、部署架构；难逆转或迁移成本高；跨模块、
>    跨维护者、跨版本兼容；依赖选型、安全模型、治理流程的重大变化；新人会反复问「为什么这样设计」。
> 4. **否决只记用户拍掉的**：不必为每条决策列出「本来也可以怎样」，只记用户明确回绝过的方案——
>    其余推演留在当次提交与存档里。
> 5. 本文件与 [roadmap.md](roadmap.md)（里程碑）、[plan.md](plan.md)（暂缓事项）交叉对账，随每次增补复查。

## 记录

### D1 · 节点不可变

- **决策**：会话树里的消息节点创建后只读；用户「改」一条消息 = 以它为父创建同级新节点（Revise），旧节点留在树里。
- **为什么**：崩溃安全（任何时刻落盘的都是合法的树）与分支对比（同一父下并列多个版本，可来回切）。就地可变省一次拷贝，代价是每次编辑都在破坏「已提交即事实」这条前提。

### D2 · Revise 的 `Carry` = 边转移

- **决策**：`Carry` 模式只转移边——新节点接管旧节点的孩子，并改写这些孩子的父指针，不复制任何节点。
- **为什么**：拷贝子树会让数据翻倍、同一段对话出现两份身份；`Carry` 的语义是「接着往下写」，历史本身没有变。
- **后来**：深拷贝子树被立为并列的第三模式（`Clone`，D96），但那是显式选用，不是 `Carry` 的实现方式。

### D3 · 流式中间态不进领域

- **决策**：增量只流经 UI；一个 Turn 结束才一次性 Commit 一个不可变节点。
- **为什么**：半节点（写了一半的消息）会让不变量、恢复与并发全部复杂化，而 UI 本来就有自己的草稿层。
- **后果**：执行中崩溃 → 该 Turn 整节点未提交，文本随失，树仍合法。

### D4 · 三方插件协议 = MCP

- **决策**：Tier-2 插件协议用 MCP，由 `mcpgate` 适配成 `port.Tool`，不自造 JSON-RPC。
- **为什么**：接入成本与生态——别人已经写好的 server 直接能用；自造协议等于要求每个接入方再写一遍客户端。

### D13 · 内置能力不享特权

- **决策**：内置工具、存储与模态适配器一律经端口契约接入，内核（`app`/`domain`）不直连任何具体实现。
- **为什么**：给内置开一个直连口子，内核就会顺着「这次特殊」长出对具体实现的依赖，插件面与内置面从此两套语义。

### D14 · 横切能力走装饰器

- **决策**：重试（含 429 退避）、截断、审计这类横切能力，在装配根以端口装饰器叠加，不进插件 API、不散落进业务代码。
- **为什么**：写进业务代码后每个调用点都要记得做一遍；写进插件 API 则等于向插件承诺这些语义，接口再想收就收不回来。

### D19 · Root 实节点化

- **决策**：虚拟 Root 改成实节点——ID 复用会话 ID（Root 即会话）、新增 `RoleRoot`、去掉 `Head`/`Checkout` 的空串特例、`Prune`/`Revise` 拒 Root；旧格式破坏性切换。
- **为什么**：空串当「没有游标」是 API 里的魔法值，不变量得写两套表述；实节点化后一棵树只有一个根 ID，所有边都是真边。

### D20 · persona 进树

- **决策**：人格作为会话首节点落在树里（system 角色），内容是创建时 `system_prompt` 的快照，恒回传，可 Revise/Prune。
- **为什么**：只在装配期注入的话，人格不可分叉、不可编辑、审计不到树上；进了树，它就随会话版本一起走。

### D22 · 权限等级矩阵

- **决策**：四档等级（默认 strict）+ sandbox 特权目录；两列分工——文件看路径格、执行看工具列，互不叠加；矩阵外一律 ask；`/permission` 写回 config（取代 D6）。
- **为什么**：目录身份与权限等级是正交的两件事，家目录沙箱表达不了「特权目录 / 其他」两档；矩阵外 deny 对个人助手过严。
- **读路径恒 Allow**（外部审查后复核维持）：读不产生副作用，收紧会让每次读文件都变成一次弹窗，并让「全文可用 `file_read`」与附件链失效。这是当初的显式设计，不是漏写；真要收紧是设计变更，须另立决策。

### D23 · 记忆布局

- **决策**：全局单文件 `memories.md` + 会话级 `conversations/<id>.memory.md`。
- **为什么**：个人量级下直读直编就够；目录树只是把「放哪」变成新问题，会话记忆另立目录则要跟会话树同步两处。

### D29 · Tier-1 插件后移

- **决策**：M4 只做 Tier-2（MCP）；`pluginapi/v1` 与 `plugingo` 后移。
- **为什么**：M4 的验收只针对 MCP，双线并进会挤占 TUI、装饰器与审查遗留的容量。

### D30 · MCP 客户端用官方 SDK

- **决策**：用 `modelcontextprotocol/go-sdk`（纯 Go，stdio 与 streamable HTTP 双传输）；引入前先 spike，API 不合则回退自写 stdio JSON-RPC + `net/http`。spike 已过。
- **为什么**：帧格式、能力协商、HTTP 流重连这些 spec 细节自写易踩；cgo / Node 系客户端违背纯 Go 单二进制。
- **代价**：sdk 要求 go ≥ 1.25，`go.mod` 随之上调（后来因漏洞修复继续上调，见 D137）。

### D35 · `model.api_key` 允许明文

- **决策**：允许明文，启动打印警告（不回显密钥）；`secret:` 引用仍走 `port.Secrets`；值为空时回落 `secret:AQUARIUS_OPENAI_KEY`；文件内值优先。
- **用户拍掉**：一律拒绝明文——用户要的是「贴一把钥匙就能用」；也否掉静默启用，风险必须告知。

### D36 · 面向 agent 的文本一律英文

- **决策**：进模型上下文的字符串（system 提示、工具声明与参数描述、工具回填结果与错误）用英文；面向用户的界面、命令输出、日志用中文。
- **为什么**：模型上下文的口径要稳定，回复语言只应由 system 提示约束；全站改英文会让中文用户界面跟着变。

### D43 · GUI 前端 = Gio 悬浮球

- **决策**：`uigui` 以同权实现接入 `uiFrontend`（Presenter + Prompter + Confirmer），`ui.kind` 新增 `gui`；形态 = 单组件悬浮球（左键展开输入栏、右键菜单）+ 转写浮层 + 托盘常驻 + 全局快捷键 + 位置记忆；主题令牌化。
- **为什么**：Gio 是纯 Go、无 cgo，守得住单二进制。Fyne 要 cgo/OpenGL，Wails/Web UI 要前端构建链与 webview，独立 GUI 进程会把交付变成双程序。
- **代价**：Gio 没有真透明，形状只能靠形裁（后来改为整窗 ULW，见 D62）。

### D62 · 整窗 ULW 换壳

- **决策**：每帧 headless 重渲成一张预乘 BGRA 位图（内容 + 淡出带 + 元素羽化一次合成），经 `UpdateLayeredWindow` 直提主窗；形裁与独立 overlay 窗口整条退役。
- **为什么**：主窗内容、形裁、效果层三通道并存时，亚帧错位是结构必然——Gio 在 `Present` 之前就放行客户端，此后的交错点不受代码次序控制。挪次序已被三轮截图迭代判死，单通道才是根治。
- **代价**：羽化边带从「点击穿透」变成「可命中」；`e.Frame` 的 swapchain 渲染成为不可见冗余。

### D95 · 工具调用内嵌为 assistant 分片

- **决策**：`PartTool` 同片承载调用与结果（CallID / Name / Args / Result / Approval），`RoleTool` 删除；一次 Turn 只提交一个 assistant 节点（用户 : 助手 = 1:1），先执行后提交；`port` 里的 tool 角色降级为 API 投影概念；旧格式破坏性切换，不自动迁移。
- **为什么**：tool 独立节点是全树最重的机制债——存在性引用不变量、CallID 全树唯一、`Prune` 失联收敛、深拷贝重映射，五处复杂度都来自「调用与结果跨节点配对」。同片承载后，跨节点引用彻底消失。
- **后果**：既有含工具调用的会话升级后不可读（`List` 点名 ID），需手工处置；纯工具轮仍是合法节点；分叉条改为每 Turn 一个挂点。

### D96 · Revise 第三模式 `Clone`

- **决策**：`KeepMode` 新增 `Clone`——新节点（同父同角色、内容替换）+ 以旧节点为根的整棵子树深拷贝挂其下；拷贝节点 ID 全新、与原子树零共享，旧子树字节级不动；`RevisedFrom` 只在新根记一条。仅领域 API，不接命令。
- **为什么**：`Fresh` 丢后续历史，`Carry` 的子树身份绑在旧版本上；需要「复制整段历史试另一种走向、两份互不影响」。
- **与 D2 的关系**：D2 否决的是「以拷贝替代 Carry」（数据翻倍 + 身份分裂成为默认行为），`Clone` 是显式选用的第三模式。

### D105 · 文档转文本的库选型

- **决策**：pdf = `ledongthuc/pdf`，docx = `gomutex/godocx`，xlsx = `excelize`，html = `x/net/html`；pptx 与 rtf 缓（`gopptx` 在 Windows 上构建损坏，rtf 无成熟纯 Go 库），回落二进制占位。
- **用户拍掉**：自写 OOXML 解析（「尽量用现成库，不自己造轮子」）；许可证不干净的实现——`fumiama/go-docx`（AGPL 连带 GPL）、unioffice（AGPL/商业双授权）、UniPDF（商业）。
- **口径**：按扩展名分派（OOXML 是 zip 容器，内容嗅探无能为力）；解析失败回落占位并注明原因，绝不让附件摄取整体失败。

### D110 · 配置底座破坏性改造

- **决策**：数据目录 profile 化——`<data>/config.json` 只存当前 profile 指针，`profiles/<name>/` 整目录隔离（配置、会话、记忆、附件、任务、审计、沙箱）；profile 内配置改成 provider 列表 + `model.primary` + `fallback[]`；不写迁移器，识别到旧形状即报错并给迁移指引。
- **为什么**：整目录隔离让「切换 profile = 换目录」，会话与附件随之隔离；schema 一次改完，避免分两次破坏。
- **同条修订**：`gui_pos.json` 与附件落 profile 内（全局放置会跨 profile 误清）；`--profile` 在三级覆盖链之外；fallback 判据是 `ErrTransient`，重试在内、降级在外，无粘态。

### D119 · 非 Windows 门禁 = WSL 原生工具链

- **决策**：非 Windows 门禁 = 在 WSL 内用原生 Linux 工具链跑 `go build ./...` 与 `go vet ./...`，固化成 `cmd/linuxgate`；不再声称 Windows 上一条命令交叉编译可用。
- **为什么**：Gio 的 Linux 后端（X11/Wayland/EGL/Vulkan/GL）全走 cgo，`CGO_ENABLED=0` 编不过，也没有任何 tag 组合能把它们一起关掉；Windows 侧不存在 Linux 目标的 C 工具链。
- **代价**：门禁依赖本机 WSL 与一份一次性 apt 清单；只覆盖编译 + vet，不跑 Linux 下的 GUI 与测试。

### D137 · 依赖漏洞治理

- **决策**：`govulncheck` 列入门禁（改动 `go.mod` 后跑），可达漏洞清零；工具链随修复版上调（1.27.2 → 1.27.3），excelize 升到修复版。
- **为什么**：外部审查报了 5 条，实测 13 条——不体检就不知道漏洞从哪进来。而且要在**发版前**跑：`crypto/x509` 那条只有工具链补丁版才修，不看工具链版本永远看不出来。
- **顺带**：LLM 客户端在 Transport 层补 `dial 10s` + `ResponseHeaderTimeout 10min`；不能设 `Client.Timeout`，流式 SSE 头之后可能合法跑很久。

### D138 · 插件启动信任门

- **决策**：`plugins` 目录发现的条目首次连接前须确认，指纹 = sha256(transport|command|args|url)，变了重新问；config `mcpServers` 里写的条目视为用户显式信任、不过门；信任状态存 config `plugins.<name>.trusted`，随 profile 走。
- **用户拍掉**：把信任状态放 `<dataDir>/plugins/state.json`（跨 profile 串味）或另立 state.json——config.json 本身就在 profile 下，读写路径与 `enabled`/`granted` 同一条，零新机制。
- **边界**：stdio server 是任意子进程，capability 无法在 OS 层强制；能补的是「连接之前先问一次」。信任门在前、能力授权在后，两者答的不是同一个问题。

### D146 · 决策编号不进用户面

- **决策**：`D<n>` / `§<n>` / 里程碑 / 迭代标记只允许出现在 contracts / overview、decisions、roadmap、plan 与代码注释；界面文案、命令帮助、CLI 输出、面向用户的日志、README 一律不写，改为「行为 + 理由」。
- **为什么**：用户不知道 `D34` 是什么，也无法据此行动；这些是作者的工作日志，挤掉的正是最需要清晰的句子。
- **落地**：守卫测试扫非测试源码的字符串字面量，命中即失败——让铁律可执行，而不是靠记性。

### D150 · 注入节点与轮询器

- **决策**：`inject` 是领域里的独立角色（不是 system 的变体）；API 角色由装配层投影（默认 user + 数据围栏，`job:`/`poller:` 投影 system）；触发与否按来源定默认、调用方可覆盖；注入只入队，树只在会话 goroutine 里改。
- **为什么**：`system` 在 Aquarius 里带水位语义（人格快照与压缩摘要会切断其上历史），把注入塞成 system，会让「工具补一条上下文」顺手裁掉整段会话。
- **后果**：新增 `port.Injection`/`Injector`、`RoleInject`、轮询器；`job_status`/`job_logs` 保留（手查仍有用），但系统提示词不再引导模型轮询。

### D151 · 密钥存本机加密库

- **决策**：新增 `<profile>/secrets.bin`，`secret:<名>` 先查库、再查同名环境变量；Windows 用 DPAPI，其它平台 AES-256-GCM + 同目录 `secrets.key`（0600）；文件写前留一代 `.bak`。
- **用户拍掉**：保持环境变量（本项目的工具会起子进程，继承面最大）、明文文件（与现状等价，只换了文件名）、自造主密码（每次启动都要输，破坏悬浮球形态）。
- **不夸大**：三者都挡不住「以同一用户身份运行的恶意程序」，用户说明里照实写。

### D170 · 信任级显式化

- **决策**：`Injection.Trust` 三态（host / external / 零值按 external 处理），判定只看该字段、不再读 `Source` 前缀；围栏正文中和闭合标签；每次装配在首条 system 追加一句常驻声明；摘要不洗指令。信任位随节点落盘。
- **为什么**：`Source` 是生产者自报的字符串（MCP 工具名、插件名都进这条路），拿它当信任依据是 fail-open——谁能造出 `job:` 前缀，谁的内容就被当成宿主事实读。
- **不做**：围栏 nonce（上下文里没有能执行围栏的解析器）；也不新增领域角色，树里仍只有 `inject` 一种。

### D173 · 模型与提供商 v2

- **决策**：provider 管「怎么连」（name / kind / base_url / keys[] / models[]），model 管「能做什么」（caps: tools/reasoning/vision，集合语义，省略按协议缺省）；生效能力 = 整链取与；`fallback` 逐项 `{provider, model}`；`keys[]` 密钥池按序轮换、逐把独立冷却；破坏性升级，不写迁移器。
- **为什么**：`vision` 挂在 provider 上是错的（同一家不同模型不一样）；fallback 写成 provider 名列表表达不了「同家的便宜型号」；`api_key` 单值撑不住多账号。
- **代价**：加一条弱模型会静默削能力，所以启动打一行警告、`/model` 逐项标注是哪一环拉低的。

### D175 · 多协议适配器

- **决策**：`kind` 选协议（`openai-chat` / `openai-responses` / `anthropic`），一个 `port.LLM` 实现一套映射，其余装饰器不感知协议；`base_url` 是路径前缀；`PartThinking` 增 `Signature`，**协议前缀随值存**（跨 provider 复制会话时不会把 A 家的签名发给 B 家）；`unsupported_params` 只对 `openai-chat` 生效。
- **为什么**：三家的 `port.LLM` 语义一致，差异全在线上格式；思考块续跑必须原样回传（Anthropic 的 `signature`、Responses 的 `encrypted_content`），丢了就续不上。
- **不做**：Responses 的服务端会话（本产品自己管树）、Anthropic 的显式缓存、增量事件透传。

### D179 · 语音：厂商适配器的 ASR 与 TTS

- **决策**：ASR/TTS 走厂商 chat-completions 的音频形状（协议位 `chat-audio`）；`audio.asr`/`audio.tts` 引用 provider、只借 `base_url` 与密钥池，不进降级链；不复用 LLM 装饰器链；转写回填输入框、不直发；整段合成后播放。
- **为什么**：MiMo 的 ASR/TTS 都长在 `/chat/completions` 上，不是 `/audio/transcriptions`；音频模型不是对话模型的替补，播报失败降级成另一个音色比不播更怪；ASR 有误差，直接发送等于替用户按了回车。
- **边界**：采集只有 Windows、只有默认设备；风格控制（指令 / 标签 / 音色）是配置项，进设置窗并可试听。

### D197 · 联网能力提供商化

- **决策**：`port.WebSearch` / `port.WebFetch` 各一个方法，适配器一家一个目录；`web.search.providers` / `web.fetch.providers` 是有序列表，网络类错误换下一家、400 不换、同一家连败 3 次冷却 60 秒；`webfetchlocal` 无需密钥、缺省装配；两件工具常驻，未配置时明确报因。
- **为什么**：托管 `web_search` 绑模型且来源不可审计；只接一个搜索 MCP server，则「用哪家、什么顺序、失败怎么办」交给插件，用户无法统一配置。
- **口径**：回填如实标注实际提供商与失败过的提供商——这是降级唯一在会话树里留痕的地方。

### D198 · 本地抓取的安全默认

- **决策**：校验在拨号层（解析后逐个 IP 判回环/私网/链路本地/组播/未指定）；重定向逐跳复核（最多 10 跳）；遵守 robots.txt（按 host 缓存 10 分钟）；5 MB 响应、30 秒超时、只收 HTML/文本；`allow_private_ips` 缺省关。
- **为什么**：模型能自己造 URL、网页也能放跳转，「读一个链接」很容易变成「读内网面板或云元数据」。只查 URL 字符串挡不住 DNS rebinding 与 302 到内网，所以校验必须落在拨号层。
- **补充**：用户配的代理常在本机，拨号层放行代理地址，但请求前另做一道目标解析，把私网判定补回来。

### D201 · 技能 = 目录 + `SKILL.md`

- **决策**：格式跟 Agent Skills（目录 + YAML frontmatter + Markdown），不自造；技能根 = `config.skills.dirs` + `<profile>/skills` 兜底，向下最多 2 层；三级渐进披露（name/description 进工具描述、命中才载入正文、其余走 `file_read`/`term_exec`）；正文进工具回填或注入节点，**绝不进 system**；`skill` 工具常驻。
- **为什么**：本仓无工作区概念，不能照抄「从 cwd 向上找」；正文进 system 会让人格变成两份事实源，用户改人格时不可预期；正文留在树里，压缩时才丢——这正是渐进披露想要的按需占用。
- **信任**：技能正文是「用户安装、要求模型遵循的指令」，回填带一句英文前缀说明；技能目录里的其它文件仍是数据。

### D204 · 采样参数开放到配置与设置窗

- **决策**：`model.sampling` 是整链缺省，`models[].sampling` 逐模型覆盖；浮点参数用指针（nil = 不发送、0 = 真发 0）；不做 `/sampling` 命令；协议约束如实报因；热生效。
- **为什么**：`temperature: 0` 是「要确定性输出」这个有意义的取值，沿用「零值 = 不发送」就永远表达不出 0。
- **协议约束**：Anthropic 只接受 `temperature ∈ [0,1]`，超范围按名报因、不静默截断；开扩展思考时该协议要求温度为 1 且不接受 `top_p`，适配器两个都不发。

### D210 · 首跑必走装配前向导

- **决策**：首跑一律先开装配前向导（即使密钥已能从环境变量取到），填完保存即置 `welcomed`；三条探测路径改走 `resolvePatchKey`（同解析口径、不打「已落盘」警告）。
- **为什么**：用户实测报了两件事——两条一模一样的明文警告（欢迎窗的草稿被当成已落盘，两个按钮各解析一次），以及欢迎窗与主窗同屏（「配置够用」被当成了「用户已确认过」）。
- **边界**：非首跑且密钥可用的日常启动不再弹窗；取消仍是退出且不写 `welcomed`。

### D211 · 分层方向由架构测试守护

- **决策**：`internal/arch` 用 `go/parser` 读全仓生产文件的 import，按目录映射层，断言 `adapter → port ← app → domain`，另加两条反向约束（`cmd` 只进不出、`uigui` 不被内部包依赖）；adapter 同层互引合法。
- **为什么**：依赖方向此前只靠人记。52 个包 0 违规，但没有测试会在有人从 `app` import 具体适配器时变红——这类错误只在下一次重构时暴露，而那时代价已经是重写一层。
- **自检**：判定函数自带正反例用例，因为守门测试最大的失败模式是「永远绿」。

### D214 · 聚合根经 `Snapshot`/`Restore` 搬运

- **决策**：三张结构表私有、读一律走访问器；`Snapshot()` 导出确定性的只读副本，`Restore()` 是唯一重建入口且进来先跑 `Validate`；`storejson` 自带 wire DTO，`Conversation` 删除全部 JSON tag。
- **为什么**：导出字段加 JSON tag，等于领域在替适配器定义「磁盘上长什么样」——任何人都能一行绕过所有不变量检查，连 `.bak` 兼容这种纯持久化问题都只能到领域里解决。
- **边界**：`Message` 不做 wire DTO（不可变值对象、序列化形状稳定）；结构表归适配器，节点负载留在值对象上。

### D215 · 变更后整树自检放在 build tag 后面

- **决策**：`ValidateEveryChange` 在 `-tags aqvalidate` 构建时为真，四条变更路径末尾跑全树 `Validate`；生产构建是常量 `false`，检查被编译掉、零开销。
- **为什么**：变更方法只校验传入节点、不校验产出的整棵树，一条打破不变量的路径要等到很久以后某次读树才炸，报错位置与肇事改动完全脱节。
- **用法**：改领域变更路径时跑 `go test -tags aqvalidate ./...`。

### D217 · 收口与拆包并入 v0.2.0

- **决策**：原 v0.3.0 的七项内部结构工作并入 v0.2.0；顺序是先做不动 import 面的收口，再拆端口与归位，最后才搬文件；其中 `uigui` 拆包一项后被 D234 撤销。
- **为什么**：v0.1.0 发布当天用户面几乎没有待交付的新功能，而结构大改推到下个版本，会与下一批功能改动撞在同一组提交里，届时分不清「行为变了」还是「只是搬了文件」。
- **口径**：版本号只表达「一批可验证的收口」，不表达时间。

### D222 · 联网与语音的提供商可独立配置

- **决策**：`webProvider` 与 `audioChannel` 各加 `base_url` / 密钥字段；解析顺序 = 显式字段 → 借 `from`/`provider` 指的条目 → 密钥回落按侧/按能力派生的名字，借只补缺的那一项；`from`/`provider` 保留为兼容简写；密钥槽按侧（`_SEARCH_`/`_FETCH_`）与按能力（`_ASR`/`_TTS_`）分开。
- **为什么**：联网与语音往往是另一家、另一把钥匙；借不到就只能改对话 provider，而那一改会连带换掉主模型。
- **口径**：界面只写显式字段；「填入」抄端点与密钥**引用名**，永不抄值。

### D223 · 语音按协议位分派

- **决策**：`kind` 是唯一分派依据（asr 四档 `chat-audio`/`whisper`/`openai`/`funasr`，tts 三档 `chat-audio`/`vits`/`gptsovits`），白名单外 fail-fast；本地识别走进程内 whisper.cpp（WASM 翻 Go，无 cgo），只读 `model_path`；繁转简在装配处叠一层，自写最长前缀匹配 + 内嵌 OpenCC 词典。
- **为什么**：这三件事的共同点是换一种线上协议，不是「再来一个模型」；模型名不决定协议（`whisper-1` 既可能是官方也可能是本地 server）。
- **不引**：第三方 ASR 客户端（只覆盖 OpenAI 形状、输入锁死）；把 whisper 做成插件（推理引擎塞进插件宿主，生命周期与崩溃隔离都会变复杂）；模型下载器；直接引 `liuzl/gocc`（传递依赖 GPL-2.0，静态链会把整份交付拖进 GPL）。
- **代价**：二进制 +18 MB；每个模型实例预留 4 GiB 虚拟地址空间，装配期只建一个；`GOEXPERIMENT=simd` 是构建期开关，不开慢 4 倍。

### D234 · `uigui` 拆包本版不做

- **决策**：本版不建子包，只做「大文件按职责拆文件」；拆包移入 backlog，将来出现第二个前端或第二个主题消费者时重新算。
- **为什么**：实测三个候选包只占 24%，搬完父包仍剩 1.5 万行、最大单文件不变——「单文件太大」一条都没解决；代价却是 391 处按类型改名（主题令牌要导出）与 75 个白盒测试的夹具重写。

### D241 · 测试自足、替身不许假绿

- **决策**：测试必须自足——不设环境变量、不依赖本机路径/密钥/服务就该全绿，要变量就 `t.Setenv`；替身里能让连接中断的写法（panic、`WriteHeader(0)`）一律按失败处理：接管 `ErrorLog` 判失败，并断言目标分支真被走到。
- **为什么**：外部 review 抓到的两处都成立——一个用例只在「本机恰好设了环境变量」时通过；另一个用例因为假服务 panic 被当成「网络错误 = 无结论」，期望正好满足，而视觉分支从未被真正走到。这类假绿比失败更安静，方向还恰好是「看起来验过了」。

### D242 · 会话进出：一份无损、三份互通

- **决策**：`aqx`（落盘 wire 形状 + 附件字节，可原样回来）、`chatgpt`（它的 `mapping` 树，事实标准）、`openai`/`sillytavern`（线性，只取 Head 路径）；导入走 `Restore` 自检、落新会话不覆盖；思考/工具/附件在线性里丢弃并计入回执，`inject` 降级成 `system` 而不是 `user`。
- **为什么**：备份要求原样回来（少一个字段就是丢数据），喂给别人要求符合别人的规范（多一个字段别人就报错），混在一起会做出两头不讨好的东西。
- **用户拍掉**：Markdown 当导出格式（它不是可再导入的规范）；线性导出自动挑最长分支（猜错不可解释）。
- **不复用 `port.OutputAdapter`**：那是「每提交一条回答就扇出一次」，而导出是用户点一次、作用于整棵树。

### D243 · 角色卡只读导入

- **决策**：原卡 JSON 逐字节留档（未知键不丢），`.charx` 整包留档；投影 = 用户人格 + 卡的人格段，卡的 `system_prompt` 默认作附加段、开关打开才替换；示例走 `Trust=host` 注入节点（可被压缩挤掉）；尾部指令走会话 `Tail` 字段；会话记角色 slug；导入是用户面动作，不提供模型可调用的工具。
- **为什么**：只存投影等于「我们认识的字段 + 我们做的取舍」，而导入是单向的，丢了就真丢了；用户人格承载着他自己的规则与安全约束，静默替换是会造成真实损失的默认值。
- **修订**：人格段改模块化、替换态保留 `@env`、上限放宽——现行口径见 D247。

### D244 · 复杂任务转交给外部代理（ACP 客户端）

- **决策**：我们只当 ACP **客户端**（v1、六方法面、不申报 `fs`/`terminal`/`elicitation`）；端口 `Delegate` + `acpgate`，模型可调 `delegate`（Confirm、Interactive，ESC → `session/cancel`）；回填 = 报告 + 一行摘要，转录不进树；每次全新会话但契约留复用位；发现 = 配置 + PATH 探测，不内置预设、不自动安装。
- **用户拍掉**：自己做子 Agent 编排、当 ACP 代理让编辑器选我们、申报 `fs`/`terminal`、把子代理转录进树、转发我们的 MCP server 给它、内置预设与自动安装、复用子代理会话、让用户手写任务描述再触发转交。
- **边界如实写**：`workdir` 是起点不是围栏，我们的权限矩阵管不到子代理——批准一次转交 = 批准那个程序在它自己判断下动手。这条不写成「我们会拦住它的危险操作」。

### D245 · 命令注册表

- **决策**：一条记录 = {名字们, 参数用例, 描述, 处理函数}；`/help`、补全浮层与分派读同一张表；别名是同一条记录的多个名字；静态表保持包级不可变，动态命令（`/mcp:*`）仍在 `Commands()` 处合并。
- **为什么**：此前 `/help` 读一张表、执行读 29 个 switch 分支，两处维护同一条事实；测试只能发现漏改，不能让漏改不发生，而 v0.3.0 一次要加七条命令。

### D246 · 文件对话框按用途分开

- **决策**：分成 `OpenRequest`（打开一个文件）与 `SaveRequest`（另存为），各带用途、标题与过滤器表；与附件多选、技能目录选择各走各的；保存框不设覆盖确认（重名由命令面加 `-2` 并在回执写清落点）；标题 → 文件名派生上移 `port.FileStem`；缺省扩展名全层不带点。
- **为什么**：复用多选那条路，会让两处都长出「这次只许多选/不许」的分支；保存框里先问「要覆盖吗」再被命令面的防覆盖规则存成另一份，两句话就对不上。防覆盖只留命令面一个事实源。

### D247 · 角色卡按字段进人格模块树

- **决策**：`@char.identity` / `description` / `personality` / `scenario` 作子模块，`@char.system` 与 `@char.book` 平级，用户可单独挪或删；条件内置（空模块不计缺失），所以 `@char.*` 可永久留在 `prompts.persona` 里；替换模式保留 `@env`，`U` 重定义为不含 `@env`；常驻世界书默认注入（`constant && enabled`）；`mes_example` 加开关；宏替换集中成一份纯函数（大小写不敏感、容忍括号内空格、认不出原样保留、不递归）；上限按真卡放宽到单卡 64 MiB / 卡 JSON 32 MiB。
- **为什么**：一段拼接挡住了三件事——用户没法按自己的说法重排卡的哪一段；「附加 / 替换」两模式表达不了；实测有卡三件套全空、人设整个写在 `character_book` 的 `constant` 条目里。
- **用户拍掉**：保持单串拼接；只把 `system_prompt` 做成模块；替换模式连 `@env` 一起丢（那是运行事实，不是人格）；给 `@char` 组写组头文本（会被「空组不出」吞掉）；把常量世界书做成注入节点（会套围栏、会被压缩吸收）；净化卡文本里的 HTML（模型看到的与用户看到的就不是同一份）；给常驻世界书设聚合上限（会让那类卡整张不可用）。

### D248 · 保存框的「保存类型」就是格式选择器

- **决策**：过滤器由 `ExchangeFormats()` 里可写条目生成，一档一种、同序同数，第一档恒 `aqx`；档位从 `OPENFILENAME.nFilterIndex` 取，不按扩展名反推；非 Windows 平台报 `-1`，宿主按扩展名回落（`.jsonl`→sillytavern、`.json`→chatgpt、认不出→aqx）；落点扩展名随档位改正。
- **为什么**：界面能做的事不该比命令行少，而「给别的程序读」正是那三份格式唯一的用途。按扩展名反推必错——用户可以写任何扩展名，也可以换了档不改文件名。

### D249 · `aqx` 一个归档装一组会话

- **决策**：`manifest.json` 带清单 + `conversations/<i>/tree.json` + 跨会话共用的 `blobs/`（版本仍是 1，旧单树形状不再读）；不带 `--pick` = 全部导入，`--pick` 序号 1 起；多会话只对 aqx 成立，其余格式多于一个直接报错；界面先弹勾选面板（只有一个会话时不弹）；先全部自检再一次性落盘；上限按会话算。
- **用户拍掉**：保持一次一个会话；为多会话升版本号；读旧单树形状；不带 `--pick` 时只导第一个；0 起序号；多会话时静默只写第一个；界面自己解 ZIP 拿清单；边解析边入库；把清单标题当导入后的标题。
- **为什么**：备份是整库动作，「一份文件 = 一次完整备份」；共用附件库让同一个附件被十个会话引用也只占一份字节。

### D250 · 命令补全浮层扩到参数相

- **决策**：文本以 `/` 开头即开浮层——**空格把浮层从命令相切到参数相**，不再关闭（D103 的「参数级补全不做」作废）。参数相按**末尾 token** 算（不看光标、不解释引号）；候选来自注册表新增的逐参数声明 `Params`（枚举给可选值、自由文本只给一句不可填的提示）；键位 = `Tab` 轮换（首按锁定候选表并填第一项，此后依次替换同一段 token）、`Shift+Tab` 同一套轮换但逆向（首按落末项）、`Enter` 恒提交不兼职补全、`Esc` 关浮层；点某行 = 按一次 Tab（填进输入框）。GUI 顺带补上输入历史（↑↓ 在收起态单行时翻，去重相邻、上限 50、翻到底回草稿）。
- **为什么**：D103 期否决参数补全的理由是「没有可依的数据」——参数只有一句 `Usage` 速记，逐参数反解 `[--keep|--copy]` 这类分组写法只会猜错。D245 把元数据收成了一张表，参数声明就落在同一条记录里，条件已经变了。每次都要回头翻 `/help` 才能确认一个枚举值叫什么，是这一层缺失的直接代价。
- **用户拍掉**：`↑↓` 移动浮层高亮（那是用户的输入历史，按习惯就该翻历史）；`Enter` 兼做补全/提交双语义（同一颗键两种意思，误发一行的代价是把它送进对话）；补全落笔带尾随空格（那样下一次 Tab 从「新参数开头」重算，轮换接不上）；`Shift+Tab` 留在窗口的焦点导航（浮层开着时它和 Tab 是一对方向键，留给系统切焦点等于把「按过头退回去」这个动作抽走）。
- **边界**：按末尾 token 算而不追光标——追光标要复刻编辑器的换行与引号状态，收益只在「回头改中间那个参数」这一种用法上；引号不做解释（`/import "C:\My Docs\x.aqx"` 的引号内仍算一个 token，用户想补的话只能先写完）；`Usage` 保持手写不动（`/help` 输出逐字不变），与 `Params` 由注册表自检对账。
