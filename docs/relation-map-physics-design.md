# 关系图「全程物理动画」重构设计（D124）

> 状态：**已批准并实现（2026-10-09，D124）**。对应 `internal/adapter/uigui/relmap_layout.go`（布局内核）与
> `relmap_frame.go`（帧层）的重构已落地。本设计**取代**现有「一次性求解 + 静止 + 入场 lerp」
> 的布局/动画方案，不沿用 `relation-map-design.md` 的旧口径（用户指示）。
>
> 一句话：**布局器改成常驻物理模拟**——节点间边弹簧 + 斥力 + 阻尼 + 速度积分，
> 树在任何时刻都是「活的」；拖节点 = 钉住一个质点，整棵树经弹簧/斥力按物理规律动起来，
> 阻尼使其自然收敛。
>
> 落码差异（与草稿的偏差，详见 [decisions.md D124](decisions.md)）：
> ① 边弹簧改**父子等大反向**（牛顿第三定律，原草稿只对子施加——否则共振不收敛）；
> ② 静息锚由「仅根锚」改为**每节点锚**（钉住平衡态 ≈ 静息布局、快速收敛）；
> ③ 斥力**排除祖先-后代对**（原只排父子）——否则链/主干被纵向斥力拉长；
> ④ 积分加**每帧 6 子步**（高自由度节点的显式刚度会越稳定边界 → 极限环，子步压回稳区）；
> ⑤ 播种由「全叠根点」改为**向根收缩 `relSeedShrink`**（控制展开时长，避免长链被速度限幅拖到数秒+）。
> 参数档位已由 spike 调定并固化为 const（见 relmap_layout.go 顶部与 D124）。

## 1. 目标与动机

### 1.1 用户反馈（2026-10-09）
- 现状「不拖直接不动」：布局一次性解完就静止，树是「死的」。
- 用户要的**不是入场动画**（D123 的 lerp 方案被否），而是**全程都能动**：
  节点间**弹簧、斥力**，有**阻尼**；用户拖节点时，**整棵树都按物理规律动起来**。
- 隐式要求：60fps（200 节点）、收敛后不烧资源（R3）、拖拽不瞬跳、树保持可读。

### 1.2 现状问题（为什么重构）
| 现状 | 问题 |
|---|---|
| `relax()` 梯度下降（`x += F·gain`，无速度） | 无惯性 → 拖拽只推、不荡；树静止后是死的 |
| 一次性全解 + 静止 | 「不拖直接不动」 |
| 入场动画 = 根点 lerp | 是「特效」，不是物理；按下即打断 |
| y 层序硬投影 | 与 2D 物理冲突（被拖节点 y 被钉死） |
| 拖拽 = 每帧 `relax(relFrameIter, pin)` | 增量但无动量传递，整树响应弱 |

### 1.3 目标
1. **常驻物理**：任何时刻树都是一个可被扰动、会按物理回应的系统。
2. **整树响应**：拖一个节点 → 边弹簧带动子树、斥力推开邻居、动量在树间传播，整树动起来。
3. **阻尼收敛**：扰动消失后 ~1s 内自然静止；静止即停帧（R3 不烧资源）。
4. **可读**：静止态 = 规范树形（层距 + 兄弟槽位），不缠绕。
5. **60fps @ 200 节点**（≤ hardCap 240）。

## 2. 物理模型

### 2.1 质点
每个节点 = 一个质点，质量 `m = 1`（可选：`m = weight`，先取 1 简化）。状态 = 位置
`(x, y)` + 速度 `(vx, vy)`。世界坐标 dp，y 向下（对话推进方向，与现状一致）。

### 2.2 力（每帧累计到 F）

**① 边弹簧（结构性主力）**
子节点 `i`（父 `p`）被拉向「**父当前位置 + 静息偏移**」：

```
restTarget_i = ( x[p] + restOff[i] ,  y[p] + relRowGap )
F_i += kSpring · (restTarget_i − pos_i)
```

- `restOff[i]` = 兄弟槽位横向偏移（沿用 relAssign 扇区序 + 卡片宽 pitch，见 §3）。
- `relRowGap = 72` = 层距。
- 关键性质：**子树随父移动**——父被拖走，子被弹簧带着走（拖拽沿树传播的机制）。
- 静息时（无外力）`pos_i == restTarget_i` ⇒ 整树 = §3 的静息树形。

**② 根锚**
根被拉向原点，防整树漂移：

```
F_root += kRoot · ( (0,0) − pos_root )
```

**③ 斥力（2D，防重叠/铺开）**
全对（**排除直接父子对**——父子的间距由弹簧定义，互斥会让它们打不拢）：

```
对 i<j 且非父子：
  d = pos_i − pos_j
  d2 = |d|² + relSoft        // 软化防奇异
  if |d|² > relCut²: 跳过    // 作用半径截止（性能）
  mag = relRepelK · (deg_i+1)·(deg_j+1) / d2        // 度数限幅 relRepelMax
  F_i += mag · d/|d| ; F_j −= mag · d/|d|
```

- 软化 `relSoft` 让「初始全部重叠」时力有限（播种折叠时不会爆炸）。
- 卡片相叠的**接触推开**：现状是「y 锁死、只水平推开」。2D 下改用斥力主导分离；
  若实测仍深压，保留一条轻接触推开（沿重叠向量，仅作兜底）。**实现时 spike 定**。

**④ 拖拽 pin（交互）**
被拖节点位置硬写为指针世界坐标，速度清零：

```
if pin.Valid:  pos_pin = pin.Pos ; v_pin = (0,0)
```

其余节点**不**被直接移动——只经弹簧/斥力被带动（这就是「整树按物理动起来」）。

### 2.3 积分（半隐式欧拉，每帧一次）

```
v += F · dt
v *= relDamp                     // 空气阻尼（每帧 0.90 附近）
|v| 限幅 ≤ relVMax              // 防播种爆炸/病态输入
pos += v · dt
```

- `dt = 1.0`（固定每帧一步；**帧率相关**，见 §8 权衡）。
- 阻尼：乘性衰减 ⇒ 扰动后指数衰减到静止（~40–60 帧 ≈ 1s）。

### 2.4 收敛判定（R3）

```
kin = Σ_i (vx_i² + vy_i²)
settled = kin < relSettleEps · n
```

静止即 `settled` → 帧层停帧。任何交互（拖拽 pin、rebuild）都会注入能量 → 自动唤醒。

## 3. 静息布局（rest layout）——确定性参考

物理的平衡态（弹簧把每个子拉到 `父+偏移`）即一个**确定性树形**，独立于物理过程计算：

```
restPos(root) = (0, 0)
restPos(i)    = restPos(parent) + ( restOff[i] ,  relRowGap )
```

- `restOff`：沿用 relAssign（扇区序） + 卡片宽 pitch（`max(卡宽, relRestLen) + relSlotGapDp`）
  的兄弟并排逻辑（现 `seedSlots` 抽出为纯函数，只算 restOff、不再写初值）。
- 用途：
  1. **fitView / recenterTree 的树盒**——按静息树形算外接盒（当前物理位形会动，不适合做视场基准）。
  2. 物理播完的归宿（± 斥力的微扩张）。
- 性质（测试锚点）：有界、可复现、树形（`restY(子) = restY(父) + 72` ⇒ 静态层序单调）、
  兄弟按 restOff 有序。

## 4. 生命周期与帧循环

### 4.1 状态机（取代现状的三态 + 入场 lerp）

```
┌───────────┐   rebuild（开窗/数据变更/预算）
│  SEEDED   │──────────────► 新布局播种（§4.2），settled=false
└─────┬─────┘
      │ 每帧 step(dt, pin)（帧循环经 InvalidateCmd 续帧）
      ▼
  PHYSICS ──► 动能 < 阈值 ──► 静止（停帧；任何交互唤醒）
```

- **没有「入场动画」概念**：开窗/重排后的「长出来」就是物理从播种位形到静息位形的
  运动过程本身。
- **没有「按下即打断」**：用户操作（zoom/pan/悬停/右键）不扰动位形，物理照常；
  拖拽 = 加 pin，与物理叠加。

### 4.2 播种（rebuild 时）

| 场景 | 播种 | 效果 |
|---|---|---|
| **开窗首帧 / 全新图** | 全部叠在根点 `(0,0)` + 按层确定性小扰动（`≈8·(level+1)dp` 随机方向） | 物理从根部**向外长出来**（树形展开，~1–2s 落定） |
| **数据变更（新消息）** | **按节点 ID 保留旧位置**；新节点从父当前位置播种 | 增量形态变化——新节点物理「蹦出来」，整树几乎不重排（现场友好） |
| **预算/会话切换** | 同「数据变更」（保留交集 ID 位置） | 平滑过渡 |

- 位置保留实现：rebuild 前按全局节点 ID 记下旧 `sol.Pos`；新布局逐节点查表，
  查不到（新节点）→ 用父位置。
- 播种后速度 `v = 0`，`settled = false` → 物理立即开跑。

### 4.3 帧层（relGraph.tickLayout 重构）

```
tickLayout():
  if lay == nil: return false
  if lay.settled && dragNode < 0: return false      // 静止即停（R3）
  if dragNode >= 0:
      decay dragGrabX/Y（跟手，~120ms 归零，沿用 D122）
      pin = { Index: dragNode, Pos: dragPinWorld() }
  lay.step(relDt, pin)
  sol = lay.solution()
  more = !lay.settled || (dragNode>=0 && 偏移未衰减完)
  return more
```

- `dragPinWorld` / `grabAt` / `relGrabSlop` 原样沿用（按下抓取 + 抓取点衰减跟手）。
- 帧预算 `relaxLeft` 保留为安全兜底（病态输入下触顶即停）。

### 4.4 视场
- `fitView`（开窗首帧）：按 **静息树盒** 取最小 zoom 对准盒心（fit 下限 = 标签可读
  下限 0.75，沿用 D122）；仍装不下则锚点居中。
- `recenterTree`（拖后松手）：保持 zoom，静息树盒对准视口。
- 数据变更不重置 zoom/视场（沿用 D122）。

## 5. 拖拽交互（用户最关心的「整树动起来」）

流程（沿用 D121/D122 的抓手判定与跟手，物理部分替换）：

1. **按下**：`grabNode = hitTestSlop(press, relGrabSlop)`（宽半径补抓）；记抓取偏移。
2. **越过 slop 拖动**：`dragNode = grabNode`；每帧 `pin = dragPinWorld()`（指针世界坐标
   − 衰减中的偏移），`step(dt, pin)`。
   - 被拖节点钉在指针下（速度清零）。
   - **其余节点**：子被弹簧拉（子树拖着走）、邻居被斥力推开、再传给它们的邻居——
     **整棵树出现物理波纹**，带惯性（速度不瞬间为零），松手后会荡一下再收敛。
3. **松手/取消**：撤 pin；系统仍有残余动能 → 物理继续 → 阻尼收敛 → 静止。
4. **点击 /goto**：slop 内原地释放 = 点击（判定不变）。

## 6. 性能

- **物理步进**：斥力 O(n²)（带 relCut 截止）、弹簧 O(n)。200 节点每帧估计 < 0.3ms
  （spike 复测定档）。
- **绘制**：spike 已证 200 节点 0.52ms/帧（D123，`relmap_anim_bench_test.go`）。
- **合计 < 1ms/帧**，60fps 预算 16.67ms 的 ~5%，裕量充足。
- **R3**：静止即停帧（§4.3），不空转。

## 7. 测试策略

### 7.1 静息布局（纯函数）
- 树形：`restY(子)=restY(父)+72`；根 (0,0)；有界；可复现（两次构造逐点相等）。
- 兄弟有序（restOff 单调）；卡片不深压（静息态穿透 ≤ 卡宽 × relCardPenetrationMax）。
- 输入守卫（空/多根/父越界/自环/环）——沿用现有。

### 7.2 物理步进
- **settles**：无 pin 跑 N 步后 `settled`，位形有界、无 NaN。
- **可复现**：同输入同种子 → 逐帧轨迹一致。
- **阻尼降能**：动能总体下降、终态静止（重解一致）。
- **pin 传播**：钉住某节点并移动 → 邻居位移 > 0（整树响应）；松手后收敛回静息附近。
- **卡片不深压**：物理播完后同层穿透有界。

### 7.3 帧层
- 开窗：从根点播种 → 若干帧内位形在动 → 静止；期间所有节点在视口内（fit 用静息盒）。
- 数据变更：旧位置保留（未变节点坐标几乎不动）、新节点从父位弹出。
- 拖拽：被拖节点跟手、邻居被带动、视场不平移；松手后收敛即停。
- 点击 /goto、菜单、预算——沿用（不回归）。

### 7.4 性能基准（固化）
- `BenchmarkRelmapPhysStep200`（物理步进）、`BenchmarkRelmapAnimFrame200` /
  `BenchmarkRelmapDragFrame200`（帧，沿用，数值随物理版复测）。
- 门禁：`go test -race`、gofmt、vet。

## 8. 权衡 / 待你拍板的点

1. **静止即停 vs 永久微动**（最关键）：
   - 推荐：**阻尼收敛到静止后停帧**（R3 不烧资源；「全程都能动」= 任何时刻可被扰动、
     会按物理回应，不是永远在抖）。
   - 备选：加极小的持续环境扰动（树永远微微呼吸）——代价：永不收敛、持续烧帧，
     且 200 节点永久占用一帧预算。**不推荐**。
2. **2D 自由 vs 层带约束**：
   - 推荐：**2D 自由**（真正「按物理规律动」，拖拽会荡起来）。代价：动态中孩子可能
     短暂荡到父上方（**层序只在静息时严格成立**），树偶尔交叉。
   - 备选：y 用软弹簧拉向层带（`k_layer` 轻约束）——更可读但垂直方向不太「物理」。
3. **帧率相关**：
   - 推荐：固定 `dt=1/帧`（与现状同口径，简单）。120fps 屏上物理快一倍（收敛 ~0.5s）。
   - 备选：`dt` 用 `gtx.Now` 真实时间（帧率无关）——阻尼需指数化 `damp^(dt·60)`，
     系数更复杂。**可后置**。
4. **参数档位**（§2 系数）**实现时 spike 调**：目标观感 = 拖拽有 0.3–0.5s 的弹簧震荡、
   松手 ~1s 落定、静止树形干净不缠。
